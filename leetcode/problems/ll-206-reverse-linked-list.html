Reverse Linked List
Easy In-place Reversal Linked List
Problem Statement

Given the head of a singly linked list, reverse the list, and return the reversed list.

EXAMPLES
Input: 1 → 2 → 3 → 4 → 5 → null
Output: 5 → 4 → 3 → 2 → 1 → null

Input: 1 → 2 → null
Output: 2 → 1 → null

Each node's next pointer is redirected to the previous node, turning the chain around in place.

💬 Mock Interview

Reversing a linked list is one of the most fundamental pointer-manipulation exercises in interviews. The key is managing three pointers without losing your place in the list.

Stage 1 — Problem Introduction
IV
Interviewer
Alright, let's start. You're given the head of a singly linked list. I want you to reverse it in place and return the new head. For example, if the list is 1 → 2 → 3 → 4 → 5, after reversing it should be 5 → 4 → 3 → 2 → 1. Take a moment to think — what comes to mind first?
Me
Candidate
My first reaction is that I need to flip each node's next pointer so it points backward instead of forward. The challenge is that once I overwrite a pointer, I lose access to the rest of the list — so I need to save the next node before making any changes.
Stage 2 — Clarifying Questions
Me
Candidate
A few quick questions before I dive in:
  • Can the list be empty, or can it have just one node? I want to make sure I handle those base cases.
  • Are the node values relevant, or just the structure of the list?
  • Should I reverse it iteratively, or is a recursive solution also acceptable?
  • Any constraint on space? Is O(1) extra space required?
IV
Interviewer
Good questions. Yes — an empty list or a single node are valid inputs and should just return head. Values don't matter, only the structure. Either iterative or recursive is fine — we'll discuss both. Start with whatever feels cleaner to you.
Stage 3 — Approach Discussion
Me
Candidate
Let me think through two approaches:

Brute force — collect and rebuild: Traverse the list, push all node values into an array, then do a second pass assigning values in reverse. That works but is O(n) space and requires two passes. It also relies on node values rather than pointer surgery, which feels off for this problem.

Optimal — three-pointer in-place: Use prev = None and cur = head. On each iteration, save nxt = cur.next, flip cur.next = prev, then advance prev = cur and cur = nxt. When cur is None, prev is the new head. This is O(1) space and a single pass.
The three-pointer dance: save next before cutting the link, flip the link, then slide both pointers forward. At all times, prev is the "already-reversed" portion and cur is the "yet-to-be-reversed" portion. When cur falls off the end, prev is pointing at the new head.
Me
Candidate
I'll go with the iterative three-pointer approach — it's O(1) space, one pass, and clearly expresses the pointer manipulation we want. Ready to walk through it?
IV
Interviewer
Yes, go ahead. Walk me through the pseudocode and a trace on the example.
Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode:
Pseudocode
function reverseList(head):
    prev = None
    cur  = head

    while cur is not None:
        nxt      = cur.next      # 1. save the rest of the list
        cur.next = prev         # 2. flip the pointer backward
        prev     = cur          # 3. advance prev
        cur      = nxt          # 4. advance cur

    return prev                  # prev is the new head
Me
Candidate
Let me trace through 1 → 2 → 3 → null step by step:

Initial: prev=None, cur=1

Iteration 1 (cur=1):
  nxt = 2  (save next)
  1.next = None  (flip: 1 now points back to None)
  prev = 1, cur = 2
  List so far (reversed part): 1 → None

Iteration 2 (cur=2):
  nxt = 3
  2.next = 1  (flip: 2 now points back to 1)
  prev = 2, cur = 3
  List so far (reversed part): 2 → 1 → None

Iteration 3 (cur=3):
  nxt = None
  3.next = 2  (flip: 3 now points back to 2)
  prev = 3, cur = None
  Full reversed: 3 → 2 → 1 → None

Loop ends (cur is None). Return prev = 3 ✅
IV
Interviewer
Clean trace. What happens if the input is an empty list or just one node?
Me
Candidate
Both are handled naturally — no special casing needed.

If head is None: the while loop never executes, we return prev = None.
If there's one node: one iteration runs — nxt = None, node.next = None (unchanged), prev = node, cur = None — return the single node. Correct in both cases.

Stage 6 — Follow-up Questions
IV
Interviewer
Nice solution. Follow-up: can you implement this recursively?
Me
Candidate
Yes. The recursive idea: the base case is head is None or head.next is None — return head directly. Otherwise, recursively reverse the tail, which gives us a new head. The key insight is that after the recursive call, the original head.next node is now the tail of the reversed sublist — so we set head.next.next = head to extend the reversal, then set head.next = None to drop the old forward link. Space is O(n) due to the call stack — the iterative approach is better if space matters.
IV
Interviewer
What if you could only use O(1) extra space?
Me
Candidate
The iterative three-pointer solution I already described satisfies that exactly — only prev, cur, and nxt are used, all constant-space temporaries.
IV
Interviewer
Last one — how would you extend this to reverse only nodes in groups of k?
Me
Candidate
That's LeetCode #25 — Reverse Nodes in k-Group. The approach is: check whether at least k nodes remain; if so, reverse exactly k of them using the same three-pointer technique, then recursively connect to the result of reversing the next k-group. If fewer than k nodes remain, leave them as-is. It reuses this exact reversal logic as a building block.

✅ Full Python Solution

Python 3 — Reverse Linked List O(n) time · O(1) space 
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev, cur = None, head

        while cur:
            nxt      = cur.next      # save the rest of the list
            cur.next = prev         # flip the current pointer
            prev     = cur          # advance prev forward
            cur      = nxt          # advance cur forward

        return prev               # prev is the new head
Key Interview Tips 💡
  • Always save nxt = cur.next before overwriting cur.next — this is the most common mistake.
  • Start with prev = None — the original head becomes the tail, so its next must point to None.
  • The loop exits when cur is None, at which point prev holds the new head — never return cur.
  • Both empty-list and single-node inputs are handled without any special casing.
  • If asked for recursive: head.next.next = head then head.next = None — but this is O(n) space on the call stack.
  • This pattern is the building block for #92 (Reverse LL II) and #25 (Reverse k-Group) — mention that connection.
