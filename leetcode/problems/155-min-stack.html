Min Stack
Easy Stack Auxiliary Info Design
Problem Statement

Design a stack that supports push, pop, top, and retrieving the minimum element — all in O(1) time.

  • MinStack() — initialises the stack object.
  • void push(int val) — pushes val onto the stack.
  • void pop() — removes the element on top.
  • int top() — returns the top element.
  • int getMin() — returns the minimum element in the stack.
EXAMPLE
push(-2), push(0), push(-3)
getMin() → -3
pop()
top() → 0
getMin() → -2

Stage 3 — Approach Discussion
Me
Candidate
Okay, let me think through this systematically. The naive approach first: scan the whole stack on every getMin() call. That's O(n) per query — doesn't meet the requirement.

The key insight is that the minimum only changes at push and pop time. So instead of computing it on demand, I can store the minimum alongside each element as I push. Specifically, I'll maintain a parallel min-stack: every time I push a value, I also push min(val, current_min) onto the min-stack. When I pop, I pop both stacks together. This way, getMin() is just a peek at the top of the min-stack — O(1).

The elegant part: even when the actual minimum is popped off, the min-stack automatically reverts to the previous minimum. Does that approach make sense?
Walk through the example mentally: push(5) → min_stack=[5]; push(3) → min_stack=[5,3]; push(7) → min_stack=[5,3,3]; push(2) → min_stack=[5,3,3,2]. Pop() → both stacks lose the last element, min is back to 3. Perfect.
IV
Interviewer
That's the right idea. One quick sanity check — what if we push duplicates of the current minimum? Say the current min is 3 and we push another 3. How does your min-stack handle that?
Me
Candidate
It handles it correctly because I always push min(val, current_min) regardless. So pushing another 3 when min is already 3 pushes 3 onto the min-stack again. When we pop that 3, the min-stack still shows 3 underneath — no information is lost. Duplicates are safe.

Python 3 — Min Stack (walkthrough)
class MinStack:
    def __init__(self):
        self.stack     = []   # main stack — stores actual values
        self.min_stack = []   # parallel stack — stores running minimum

    def push(self, val: int) -> None:
        self.stack.append(val)
        # If min_stack is empty this is the first element — it IS the min.
        # Otherwise, carry forward whichever is smaller.
        cur_min = self.min_stack[-1] if self.min_stack else val
        self.min_stack.append(min(val, cur_min))

    def pop(self) -> None:
        self.stack.pop()       # remove top value
        self.min_stack.pop()   # restore previous minimum

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.min_stack[-1]  # O(1) — just peek the parallel stack

Stage 5 — Complexity Analysis
Me
Candidate
Every operation — push, pop, top, getMin — performs a constant number of list appends or index accesses. Python lists have O(1) amortised append and O(1) indexed access, so all four are O(1) time.

For space: I'm using two stacks, each of size at most n (where n is the number of elements currently in the stack). So space is O(n) total — linear in the number of pushed elements. There's no way to do better in the worst case since we must store all pushed values.

Stage 6 — Follow-up Questions
IV
Interviewer
Nice work. Three follow-ups: (1) What if you also needed O(1) getMax()? (2) Can you implement this with only one stack — no auxiliary structure? (3) What if pop() needed to return the popped value?
Me
Candidate
(1) Adding getMax(): Exactly the same pattern — just add a max_stack that stores the running maximum. Push max(val, max_stack[-1]) each time, pop together. Both get O(1). The stacks are independent so there's no conflict.

(2) Single-stack encoding: One trick is to store tuples (val, current_min) on the main stack instead of a separate list. It's still O(n) space, but you've eliminated the second list object. Another approach encodes the minimum difference into the pushed value, which can be space-efficient for small ranges but gets complicated with overflow.

(3) Returning the popped value: Trivial to add — just save val = self.stack[-1] before popping, then return it. No structural change needed.
IV
Interviewer
Good. One more thing — could you generalize this to a stack that tracks any aggregate in O(1), not just the minimum?
Me
Candidate
Yes — as long as the aggregate can be recomputed incrementally and is reversible on pop. Sum is a classic example: maintain a running sum alongside each entry. Max and min work too. But something like the median doesn't fit this pattern because you can't update the median in O(1) from the previous median when pushing or popping — you'd need a more sophisticated structure like two heaps for that.

✅ Full Python Solution

Python 3 — Min Stack O(1) all ops · O(n) space 
class MinStack:
    def __init__(self):
        self.stack     = []
        self.min_stack = []

    def push(self, val: int) -> None:
        self.stack.append(val)
        self.min_stack.append(
            min(val, self.min_stack[-1]) if self.min_stack else val
        )

    def pop(self) -> None:
        self.stack.pop()
        self.min_stack.pop()

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.min_stack[-1]
Key Interview Tips 面试要点
  • Always pop both stacks together in pop() — forgetting this is the most common bug
  • The min-stack stores the running minimum at each depth, not just the current element's value
  • Handle the empty min-stack on the first push() — use an if self.min_stack else val guard
  • Duplicates are handled correctly without special-casing because we always push min(val, cur_min)
  • This "parallel auxiliary stack" pattern extends to max, sum, or any incrementally-updatable aggregate
