Palindrome Linked List
Easy Fast & Slow + Reversal Linked List
Problem Statement

Given the head of a singly linked list, return true if it is a palindrome, or false otherwise.

A palindrome reads the same forwards and backwards.

EXAMPLES
Input: 1 → 2 → 2 → 1  →  true
Input: 1 → 2  →  false

The challenge: a linked list has no random access and no obvious way to read backwards. The key insight is to reverse the second half in-place, then compare.

My first thought is that palindrome checks are easy on arrays — just compare left and right pointers moving inward. The tricky part with a linked list is that you can't traverse backwards. So the question becomes: how do I efficiently read the second half in reverse order?

Integer values. Modifying the list is fine — but I'll be curious whether you could restore it. There's no strict O(1) space requirement, but I'd like to see if you can achieve it.
Stage 3 — Approach Discussion
Me
Candidate
Two approaches:

Simple O(n) space: Traverse the list, push all values into an array, then use two pointers to check if it's a palindrome. Easy to code but uses O(n) extra space.

Optimal O(1) space — three-step approach:
  1. Find the middle with fast/slow pointers.
  2. Reverse the second half in-place.
  3. Compare the first half against the reversed second half node by node.

The O(1) approach is more involved but demonstrates real linked-list skill. I'll implement that.
The reversal step is the heart of this problem. After finding slow at the middle, I run a standard in-place reversal from slow onward. Then I have two sub-lists: the original first half (from head) and the reversed second half (from prev after reversal). I compare them node by node. For odd-length lists the middle node is shared by neither half — it gets ignored naturally since the reversed half is shorter.
Me
Candidate
One important nuance: for odd-length lists, the middle node belongs to neither half — the reversed half will simply be shorter, and since I drive the while loop with right (the shorter pointer), I never over-read. It handles itself cleanly.
IV
Interviewer
Sounds good. Let's see the code and a trace.
Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode for all three steps:
Pseudocode — Three Steps
function isPalindrome(head):

    # Step 1: Find middle with fast/slow
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    # slow is now at the start of the second half

    # Step 2: Reverse second half in-place
    prev, cur = None, slow
    while cur:
        nxt = cur.next
        cur.next = prev
        prev = cur
        cur = nxt
    # prev is now the head of the reversed second half

    # Step 3: Compare both halves
    left, right = head, prev
    while right:                   # right (shorter) drives the loop
        if left.val != right.val:
            return False
        left = left.next
        right = right.next
    return True
Me
Candidate
Let me trace through 1 → 2 → 2 → 1 step by step.

Step 1 — Find middle:
Start: slow=1, fast=1
Iteration 1: slow=2, fast=2 (fast.next.next = node[2])
Iteration 2: slow=2 (third node), fast=None (fast moved past end)
Loop ends. slow is at the third node (value 2).

Step 2 — Reverse from slow onward:
The second half is: 2 → 1 (nodes 3 and 4)
prev=None, cur=node[2 val]
  Pass 1: nxt=node[1], cur.next=None, prev=node[2 val], cur=node[1]
  Pass 2: nxt=None, cur.next=node[2 val], prev=node[1], cur=None
Reversed second half: 1 → 2, head = prev = node[1 val]

Step 3 — Compare:
left=node[1 val] (original head), right=node[1 val] (reversed tail)
  1 == 1 ✓   advance both
  2 == 2 ✓   advance both
right is now None → loop ends → return true ✅

Now for 1 → 2:
slow ends at node[2]. Reversed second half: just 2.
Compare: left.val=1, right.val=2. Mismatch → return false ✅
IV
Interviewer
Excellent. What happens with an odd-length list like 1 → 2 → 1?
Me
Candidate
For 1 → 2 → 1: slow lands at the middle node (value 2). We reverse from slow, giving reversed second half: 2 → 1. Wait — let me re-examine. slow=node[2], and we reverse [2, 1] to get 1 → 2 with prev=node[1 at end].

Comparing: left starts at head (val 1), right starts at the reversed tail (val 1).
  1 == 1 ✓   advance — right is now node with val 2, left is node with val 2.
Wait — but the reversed second half has length 2 and the first half has length 1 up to the middle. Actually, right still has two nodes so we'd compare left's second node (val 2) against right's second node (val 2) too. But that's fine — all values still match → true ✅.

The key insight is that even if right overshoots into "shared" territory it still works because the list is symmetric. In practice the middle is in both halves but the values always match.

Stage 6 — Follow-up Questions
IV
Interviewer
Can you solve this without modifying the list at all?
Me
Candidate
Yes — use a stack. Traverse the list once, pushing the first half of the values onto a stack. Then traverse the second half, popping from the stack and comparing. Since a stack is LIFO, the popped values come out in reverse order — exactly what we need. This is O(n) time and O(n) space. It's simpler to code but uses more memory.
IV
Interviewer
After your O(1) solution modifies the list, can you restore it?
Me
Candidate
Yes. After the comparison step, simply reverse the second half again — applying the exact same reversal algorithm to prev. This restores the original next pointers. Then reconnect: find the tail of the first half (advance from head until node.next points into the second half), and set its next back to the restored second half head. It's extra code but not extra complexity — still O(n) time, O(1) space.
IV
Interviewer
Good. One last one — what if the list has an odd number of nodes? How does your algorithm handle the true middle node?
Me
Candidate
The middle node doesn't need to match anything — in a palindrome of odd length it's the axis of symmetry. My algorithm includes it in the reversed second half, but since the comparison loop runs while right is not None, and both sides are symmetric, it never causes a false mismatch. An alternative phrasing: we only need to compare the n // 2 pairs of outer nodes, and that's exactly what the algorithm does.

✅ Full Python Solution

Python 3 O(n) time · O(1) space 
class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        # Step 1: Find middle
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        # Step 2: Reverse second half
        prev, cur = None, slow
        while cur:
            nxt = cur.next
            cur.next = prev
            prev = cur
            cur = nxt

        # Step 3: Compare
        left, right = head, prev
        while right:
            if left.val != right.val:
                return False
            left = left.next
            right = right.next
        return True
Key Interview Tips 💡
  • This is a composition problem: it combines three sub-skills — find middle, reverse list, compare. Name each step explicitly.
  • The comparison loop uses while right (not while left and right) — right is always the shorter or equal side, so it correctly terminates.
  • Mention the stack-based O(n) space approach first, then offer the O(1) upgrade — this shows you can communicate trade-offs.
  • If asked to restore the list: reverse the second half again after comparing, then reattach it to the first half's tail.
  • Building blocks matter: if you've already solved #206 (reverse) and #876 (middle), this problem is 20 lines of glue code.
