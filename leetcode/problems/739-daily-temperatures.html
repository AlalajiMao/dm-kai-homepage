Daily Temperatures
Medium Monotonic Stack Stack
Problem Statement

Given an array of integers temperatures representing the daily temperatures, return an array answer such that answer[i] is the number of days you have to wait after the i-th day to get a warmer temperature.

If there is no future day for which this is possible, set answer[i] = 0.

EXAMPLE
Input: temperatures = [73,74,75,71,69,72,76,73]
Output: answer = [1, 1, 4, 2, 1, 1, 0, 0]

Day 0 (73°): next warmer is day 1 (74°) → 1 day wait.
Day 2 (75°): next warmer is day 6 (76°) → 4 days wait.
Day 6 (76°): no warmer day exists → 0.

💬 Mock Interview

Daily Temperatures is the gateway problem for monotonic stack — the most important stack pattern for medium/hard interviews. The key is recognising the pattern quickly. （单调栈入门题，掌握这道题就掌握了这个模式）

Stage 1 — Problem Introduction
IV
Interviewer
Here's the problem: you're given a list of daily temperatures. For each day, I want to know how many days you'd have to wait until you see a warmer temperature. If no such day exists, put zero. What are your initial thoughts?
Stage 2 — Clarifying Questions
Me
Candidate
Let me clarify a few things:
  • The output is an array of the same length as the input — each element is the number of days to wait, right?
  • Temperatures are integers, I assume? And they could range anywhere, like 30–100°F?
  • Can two consecutive days have the same temperature? If so, that doesn't count as "warmer"?
IV
Interviewer
Correct on all counts. Output is same length, temperatures are integers in range [30, 100], and "warmer" means strictly greater, so equal doesn't count.
Stage 3 — Approach Discussion
Me
Candidate
My first instinct is brute force: for each day i, scan forward until I find a day j where temps[j] > temps[i]. That's O(n²) time — workable for small inputs but not ideal.
IV
Interviewer
O(n²) noted. Can you do better?
The problem is asking for the "next greater element" to the right for each position. That's a textbook monotonic stack scenario. I should maintain a decreasing stack of indices. When a new temperature is higher than the stack top, that element has found its answer.
Me
Candidate
Yes — this is a monotonic stack problem. Here's the key observation: as I scan left to right, some days are still "waiting" for a warmer day. I can keep those waiting days in a stack. When I encounter a temperature warmer than the stack's top, that's the answer for the top day — I pop it and record the difference in indices.

The stack will always hold indices of days in decreasing temperature order (because if a day is colder than the one before it, it can't be the answer for anything above it in the stack yet).
IV
Interviewer
Good. Why store indices rather than the temperatures themselves?
Me
Candidate
Because the answer is a number of days, not a temperature. When I pop index j and the current index is i, the answer for day j is i - j. I need both indices to compute that difference. If I only stored temperatures, I'd lose the position.
Stage 4 — Pseudocode Walkthrough
Pseudocode — Monotonic Stack (Decreasing)
function dailyTemperatures(temps):
    n      = len(temps)
    result = [0] * n       # default 0: no warmer day found
    stack  = []             # indices of "unanswered" days
                             # invariant: temps[stack] is decreasing

    for i in range(n):
        # current temp breaks the decreasing order → answer found
        while stack and temps[i] > temps[stack[-1]]:
            j = stack.pop()
            result[j] = i - j   # days waited = current index − past index
        stack.append(i)       # push current index, still waiting

    # remaining indices in stack have no warmer day → stay 0
    return result
Me
Candidate
Let me trace through [73, 74, 75, 71, 69, 72, 76, 73]:

i=0, 73° → stack empty, push 0. stack=[0]
i=1, 74° → 74>73, pop 0: ans[0]=1. push 1. stack=[1]
i=2, 75° → 75>74, pop 1: ans[1]=1. push 2. stack=[2]
i=3, 71° → 71<75, push 3. stack=[2,3]
i=4, 69° → 69<71, push 4. stack=[2,3,4]
i=5, 72° → 72>69, pop 4: ans[4]=1. 72>71, pop 3: ans[3]=2. 72<75, push 5. stack=[2,5]
i=6, 76° → 76>72, pop 5: ans[5]=1. 76>75, pop 2: ans[2]=4. push 6. stack=[6]
i=7, 73° → 73<76, push 7. stack=[6,7]
End: stack=[6,7] → ans[6]=ans[7]=0 (default)

Result: [1, 1, 4, 2, 1, 1, 0, 0] ✅
IV
Interviewer
Correct. I notice you pop multiple times in a single iteration (e.g. at i=5). Does that affect the time complexity?
Me
Candidate
It doesn't, thanks to amortised analysis. Each index is pushed onto the stack exactly once and popped at most once. So across the entire loop, the total number of push and pop operations is at most 2n — the outer loop contributes n pushes, and the while loop pops in total at most n times. The overall time complexity is still O(n).

Stage 6 — Follow-up Questions
IV
Interviewer
How would you modify this to find the previous warmer day instead of the next? And how does this relate to "Next Greater Element I" (LC #496)?
Me
Candidate
Previous warmer day: Process right-to-left instead of left-to-right, or maintain an increasing stack (instead of decreasing). Scanning backwards, we're always looking at what came before.

Relation to #496: Daily Temperatures is essentially "Next Greater Element" where we return the distance (index difference) instead of the value itself. The algorithm is identical — only what we record when we pop differs. LC #496 also adds a twist where the array to query and the array to search are different, but the monotonic stack logic is the same.
IV
Interviewer
If the input were a circular array (after the last element comes the first), how would you handle it?
Me
Candidate
Classic trick: iterate 2n times using index i % n to wrap around. On the first pass (i < n) we push indices normally. On the second pass (n ≤ i < 2n) we only pop — we don't push any new index. This handles the wraparound lookup without literally duplicating the array. That's exactly LC #503 "Next Greater Element II".

✅ Full Python Solution

Python 3 — Daily Temperatures O(n) time · O(n) space 
class Solution:
    def dailyTemperatures(self, temperatures: list[int]) -> list[int]:
        n      = len(temperatures)
        result = [0] * n
        stack  = []          # monotonic decreasing stack of indices

        for i, t in enumerate(temperatures):
            while stack and t > temperatures[stack[-1]]:
                j = stack.pop()
                result[j] = i - j
            stack.append(i)

        return result
Key Interview Tips 面试要点
  • Always state the stack invariant out loud: "I maintain a decreasing stack of indices"
  • Explain amortised O(n) when asked about the nested while loop — show you understand it's not O(n²)
  • Use enumerate for cleaner index + value access
  • Know the family: #496 Next Greater I, #503 Next Greater II (circular), #84 Histogram, #42 Rain Water
  • The template is the same for all — just change what you record when you pop
