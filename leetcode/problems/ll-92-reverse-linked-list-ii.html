Reverse Linked List II
Medium In-place Reversal Linked List
Problem Statement

Given the head of a singly linked list and two integers left and right where left <= right, reverse the nodes of the list from position left to position right, and return the reversed list. Positions are 1-indexed.

EXAMPLES
Input: 1 → 2 → 3 → 4 → 5, left = 2, right = 4
Output: 1 → 4 → 3 → 2 → 5

Input: 5, left = 1, right = 1
Output: 5

The nodes before position left and after position right are left untouched. Only the segment in between is reversed.

💬 Mock Interview

This is a surgical reversal — you're not reversing the whole list, just a subrange. The elegant solution is the "front-insert" technique: repeatedly pull the node just after cur and reattach it immediately after pre. No separate reversal pass and no splice-and-rejoin needed.

Stage 3 — Approach Discussion
Me
Candidate
Two approaches come to mind:

Three-step approach — cut, reverse, rejoin: Walk to position left-1, detach the segment from left to right, reverse it using the standard three-pointer technique, then rejoin both ends. This works but requires saving four boundary pointers and it's easy to get the splicing wrong.

Front-insert technique (one pass): Walk pre to the node just before position left. Set cur = pre.next — this is the left-th node, and it will become the tail of the reversed segment. Then repeat right - left times: extract nxt = cur.next, remove it from its current position (cur.next = nxt.next), and insert it right after pre (nxt.next = pre.next, pre.next = nxt).

The key insight of front-insert: each extracted node gets placed at the front of the reversed section, naturally building the reversal without a separate pass. And cur stays fixed as the growing tail.
A dummy head before node 1 solves the left=1 edge case completely. Without it, pre would need to be None and I'd need special-case logic. With dummy: pre is always a real node — I walk it (left-1) steps, which is 0 steps when left=1, so pre ends up as dummy. Then the same front-insert loop works without any branching.
Me
Candidate
I'll use the front-insert technique with a dummy head to uniformly handle left=1. It's a single pass, O(1) extra space, and there's no separate splice/rejoin step. Want me to walk through a trace?

Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode:
Pseudocode — front-insert technique
function reverseBetween(head, left, right):
    dummy      = ListNode(0, head)    # dummy.next = head
    pre        = dummy

    # Step 1: advance pre to (left-1)-th node
    for _ in range(left - 1):
        pre = pre.next

    cur = pre.next    # cur = left-th node; will become tail of reversed section

    # Step 2: front-insert (right - left) times
    for _ in range(right - left):
        nxt      = cur.next      # node to move
        cur.next = nxt.next      # unlink nxt
        nxt.next = pre.next      # nxt points to current front of reversed section
        pre.next = nxt           # pre points to nxt (new front)

    return dummy.next

Stage 6 — Follow-up Questions
IV
Interviewer
How does this extend to reversing nodes in groups of k — LeetCode #25?
Me
Candidate
LC #25 is essentially applying this algorithm repeatedly. First, check whether at least k nodes remain starting from the current position — if not, leave the tail as-is. If yes, reverse the next k nodes using the same front-insert technique (or the standard three-pointer reversal), advance past those k nodes, and repeat. The front-insert loop becomes the inner loop of the outer k-group loop. This solution is essentially a direct generalization of what I wrote here.
IV
Interviewer
You mentioned this is a one-pass solution. Can you confirm — how many times does any node get touched?
Me
Candidate
Every node is touched at most twice: once when pre walks past it in the setup phase (nodes before position left), and once when it's either extracted by the loop or skipped as nxt.next during a pointer update. Nodes after position right are never touched at all. So yes — it's a true single linear pass; no node is revisited.
IV
Interviewer
What's the relationship between this problem and LC #206 (full reversal)?
Me
Candidate
LC #206 is the special case where left=1 and right=n (the full list). In that degenerate case, the dummy head becomes pre, we don't advance pre at all, and the loop runs n-1 times covering every node. The front-insert technique degenerates to the same result as the three-pointer iteration, just expressed differently. Conversely, #92 is the generalization of #206 — same core idea, just bounded by left and right.

✅ Full Python Solution

Python 3 — Reverse Linked List II O(n) time · O(1) space 
class Solution:
    def reverseBetween(self, head: Optional[ListNode], left: int, right: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        pre   = dummy

        # Advance pre to the node just before position left
        for _ in range(left - 1):
            pre = pre.next

        cur = pre.next   # left-th node; becomes the tail of the reversed section

        # Front-insert each node from (left+1) to right, placing it after pre
        for _ in range(right - left):
            nxt      = cur.next    # node to extract and move
            cur.next = nxt.next    # unlink nxt from its current position
            nxt.next = pre.next    # nxt points to the current front of reversed section
            pre.next = nxt         # attach nxt as the new front

        return dummy.next
Key Interview Tips 💡
  • Always use a dummy head — it eliminates the left=1 edge case entirely, no branching needed.
  • cur is the left-th node; it stays fixed and becomes the tail of the reversed segment as nodes pile up in front of it.
  • The four pointer updates in the inner loop must happen in this exact order: save nxt, unlink nxt, attach nxt to reversed front, update pre.next.
  • The loop runs exactly right - left times — not right - left + 1. The left-th node itself doesn't need to be moved, only the nodes after it.
  • When left == right: the loop runs 0 times — correct, no change, no special case needed.
  • Connect this to LC #25 (Reverse k-Group): this exact loop is the inner subroutine applied every k nodes.
