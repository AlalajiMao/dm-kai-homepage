Linked List Cycle
Easy Fast & Slow Pointers Linked List
Problem Statement

Given the head of a linked list, determine if the linked list has a cycle in it.

There is a cycle in a linked list if some node in the list can be reached again by continuously following the next pointer.

Return true if there is a cycle in the linked list. Otherwise, return false.

EXAMPLES
Input: 3 → 2 → 0 → -4, tail connects back to index 1
Output: true

Input: 1 → 2, no cycle
Output: false

In the first example, -4's next points back to the node with value 2, forming a loop.

💬 Mock Interview

Cycle detection is the canonical showcase for Floyd's tortoise-and-hare algorithm. Getting the O(1) space solution — not just the hash-set shortcut — is what separates a strong answer from an average one.

Interviewer
Alright. You have the head of a linked list. I want to know: does it contain a cycle? A cycle means if you keep following next pointers from any node, you eventually come back to a node you've already visited — rather than reaching null. Think about how you'd detect that. What's your first instinct?

My first instinct is to track every node I've seen. If I ever arrive at a node I've already recorded, there's a cycle. But that's O(n) space. I know there's a smarter way using two pointers at different speeds — if a cycle exists, they'll eventually collide.

Me

  • Is there any constraint on the number of nodes — do I need to worry about integer overflow in node counts?

Interviewer
Empty or single-node lists have no cycle — return false. The list can have up to 104 nodes, so no overflow concern. There's at most one cycle. Any correct solution is acceptable, but let's discuss both approaches and their tradeoffs.
Stage 3 — Approach Discussion
Me
Candidate
Two approaches:

Hash set — O(n) time, O(n) space: Traverse the list, adding each node's identity (not value — actual object reference) to a set. If we ever encounter a node already in the set, return true. If we reach None, return false. Simple but uses linear extra space.

Floyd's cycle detection — O(n) time, O(1) space: Use two pointers, slow and fast. slow advances one step per iteration; fast advances two steps. If a cycle exists, fast laps slow inside the loop and they'll meet at the same node. If no cycle, fast reaches None first.
Why does Floyd's work? Imagine a circular running track. If one runner is twice as fast as another, the fast one will always eventually lap the slow one — they must meet. In a list with no cycle, the fast runner falls off the edge (hits None) before any meeting can happen. The gap between them closes by 1 each step inside the cycle, so they always meet within at most cycle_length iterations after fast enters the cycle.
Me
Candidate
I'll go with Floyd's approach — it's optimal in both time and space, and it's the expected answer at this level. Ready to trace through it?
IV
Interviewer
Go ahead.
Stage 4 — Pseudocode & Trace
Pseudocode
function hasCycle(head):
    slow = head
    fast = head

    while fast is not None and fast.next is not None:
        slow = slow.next            # tortoise: 1 step
        fast = fast.next.next     # hare:     2 steps

        if slow is fast:           # same node object → cycle found
            return True

    return False                   # fast fell off the end → no cycle
Me
Candidate
Let me trace through the cycle example: 3 → 2 → 0 → -4 → (back to 2).
I'll label the nodes by value for clarity: nodes are A(3), B(2), C(0), D(-4), and D.next = B.

Initial: slow=A(3), fast=A(3)

Step 1:
  slow = B(2)
  fast = A.next.next = C(0)
  slow(B) ≠ fast(C)

Step 2:
  slow = C(0)
  fast = C.next.next = D.next = B(2)
  slow(C) ≠ fast(B)

Step 3:
  slow = D(-4)
  fast = B.next.next = C.next = C(0)... wait, B.next=C, C.next=D → fast = D(-4)
  slow(D) == fast(D) → return True ✅

They meet at node D(-4) after 3 steps.

Good. Now trace through a list with no cycle — say 1 → 2 → null.

Nodes: A(1), B(2), B.next = None.

Initial: slow=A(1), fast=A(1)

Step 1:
  Condition: fast(A) is not None ✓, fast.next(B) is not None ✓ → enter loop
  slow = B(2)
  fast = A.next.next = B.next = None
  slow(B) ≠ fast(None)

Step 2:
  Condition: fast is None → exit loop

Return False ✅
Stage 5 — Complexity Analysis
Me
Candidate
Time: O(n). If there's no cycle, fast reaches None in roughly n/2 iterations. If there's a cycle, once fast enters the cycle, it gains one step on slow per iteration — so they meet within at most cycle_length additional steps. Total is bounded by O(n).

Space: O(1). Only two pointer variables — slow and fast. No hash set, no auxiliary structure.

Stage 6 — Follow-up Questions
IV
Interviewer
Can you find where the cycle starts, not just whether one exists?
Me
Candidate
Yes — that's LeetCode #142. After Floyd's detects a meeting point inside the cycle, reset one pointer to head and leave the other at the meeting point. Now advance both pointers one step at a time. They will meet again exactly at the cycle entry node. The math behind this: if the distance from head to cycle start is F, and the meeting point is C steps into the cycle, then F ≡ C (mod cycle_length) — so walking F more steps from both positions lands them at the start simultaneously.
IV
Interviewer
What's wrong with using a visited set instead?
Me
Candidate
Nothing functionally wrong — it's O(n) time and correctly detects any cycle. The downside is O(n) space: we allocate a hash set that grows with the list. In memory-constrained environments (embedded systems, very large lists), that extra allocation matters. Also, storing object references (node identities) means the set grows proportionally to the number of nodes visited. Floyd's avoids all of that with just two pointer variables.
IV
Interviewer
What if node values are guaranteed to be unique integers from 1 to n — could you use that?
Me
Candidate
Technically yes — you could mark visited nodes by negating their values or setting them to a sentinel, then checking if you arrive at an already-marked node. But this mutates the input list, which is almost never acceptable in an interview. Floyd's algorithm is the clean, non-destructive, O(1)-space solution — it's always the right answer here.

✅ Full Python Solution

Python 3 — Linked List Cycle (Floyd's Algorithm) O(n) time · O(1) space 
class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        slow = fast = head

        while fast and fast.next:
            slow = slow.next           # tortoise: advance 1 step
            fast = fast.next.next    # hare:     advance 2 steps

            if slow is fast:          # same node object → cycle detected
                return True

        return False                  # fast reached None → no cycle
Key Interview Tips 💡
  • Check fast and fast.next — checking only fast would crash when fast.next is None and you try to advance two steps.
  • Use slow is fast (identity), not slow == fast (equality by value) — two different nodes could hold the same value.
  • Both pointers start at head — the check comes after advancing, so the initial equal state doesn't trigger a false positive.
  • Know the follow-up: #142 (find cycle start) uses the same detection, then resets one pointer to head and walks both at speed 1.
  • The hash-set approach is acceptable but always mention Floyd's and its O(1) space advantage — that's what interviewers want to hear.
  • This fast/slow pointer pattern also solves #876 (middle of list) and #234 (palindrome check) — showing that connection demonstrates pattern recognition.
