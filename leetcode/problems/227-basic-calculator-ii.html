Basic Calculator II
Medium Expression Evaluation Stack
Problem Statement

Given a string s representing a mathematical expression with non-negative integers and operators +, -, *, /, evaluate and return the result as an integer.

The expression may contain spaces. Integer division truncates toward zero.

EXAMPLES
s = "3+2*2" → 7
s = " 3/2 " → 1
s = " 3+5 / 2 " → 5

Stage 3 — Approach Discussion
Me
Candidate
The core challenge here is operator precedence — * and / bind tighter than + and -, so I can't just evaluate left to right.

A naive approach would be two passes: first resolve all * and /, then handle + and -. That works but is messy to implement.

The cleaner insight: use a stack as an accumulator of additive terms.
  • For + and -: push the signed number onto the stack.
  • For * and /: pop the last number, compute eagerly, push the result.
This resolves * and / immediately so they don't affect the subsequent additions. At the end, the stack holds only additive terms — sum them all up.
Key state to track: num (current number being built), op (the operator that preceded num). I initialize op = '+' so the very first number gets pushed onto the stack correctly with a positive sign.
IV
Interviewer
Good reasoning on the precedence. Walk me through an example — say "3+2*2".
Me
Candidate
Sure. I start with op='+', num=0, stack=[].

Read '3' → num=3.
Read '+' → operator hit. Apply op='+': push +3. Stack: [3]. Now op='+', num=0.
Read '2' → num=2.
Read '*' → operator hit. Apply op='+': push +2. Stack: [3, 2]. Now op='*', num=0.
Read '2' → num=2.
End of string → Apply op='*': pop 2, compute 2*2=4, push 4. Stack: [3, 4].
Sum stack: 3 + 4 = 7 ✅
Stage 4 — Pseudocode & Code
Me
Candidate
Here's the pseudocode before I write the real thing:
Pseudocode
function calculate(s):
    stack, num, op = [], 0, '+'    # op='+ ' seeds the first number

    for each (i, ch) in enumerate(s):
        if ch is a digit:
            num = num * 10 + int(ch)     # build multi-digit number

        if ch is an operator or last character:
            if   op == '+': stack.push(num)
            elif op == '-': stack.push(-num)
            elif op == '*': stack.push(stack.pop() * num)
            elif op == '/': stack.push(int(stack.pop() / num))  # truncate toward zero
            op, num = ch, 0             # save new operator, reset num

    return sum(stack)
IV
Interviewer
Why do you use int(stack.pop() / num) instead of stack.pop() // num for the division case?
Me
Candidate
Great question. Python's // operator performs floor division, which rounds toward negative infinity. So -7 // 2 = -4.

But the problem requires truncation toward zero, meaning -7 / 2 = -3. Using int(a / b) performs true floating-point division and then truncates toward zero, which matches the expected behavior. Using // would give wrong answers for negative dividends.
IV
Interviewer
Exactly right. Go ahead and write the final solution.
Stage 5 — Complexity Analysis
Me
Candidate
Time: O(n) — we scan each character exactly once. Each number is pushed and popped at most once, so the stack operations are amortized O(1) per character.

Space: O(n) — in the worst case (all additions, like "1+1+1+..."), every number gets pushed and none are popped early, giving O(n) stack size.

This is optimal — we must read every character, so O(n) time is a lower bound.

Stage 6 — Follow-up Questions
IV
Interviewer
Three follow-ups: (1) How would you extend this to support parentheses? (2) Can you solve it in O(1) extra space? (3) How would you handle exponentiation **?
Me
Candidate
(1) Adding parentheses: This becomes LeetCode #224. When you encounter '(', push the current running result and the current sign onto the stack, then reset state. On ')', pop the saved result and sign, combine with the current value. This essentially mirrors what our stack already does, just driven by brackets instead of end-of-expression.

(2) O(1) space: We can do two passes — first scan for * and / to produce a simplified sequence of terms (treating each resolved subexpression as a single value), then sum. However this requires modifying the string or using indices cleverly. In practice the stack approach is preferred for clarity; true O(1) space is tricky to implement cleanly.

(3) Exponentiation **: This has higher precedence than *// and is right-associative, so we'd need a separate precedence level. We could extend the algorithm with a second stack for exponentiation operands, or use a proper recursive descent / shunting-yard parser.
IV
Interviewer
Good coverage. The shunting-yard mention is exactly the right direction for a full expression evaluator. That's all from me — thanks.

✅ Full Python Solution

Python 3 — Basic Calculator II O(n) time · O(n) space 
class Solution:
    def calculate(self, s: str) -> int:
        stack: list[int] = []
        num, op = 0, '+'          # seed op='+' so first number is pushed as-is

        for i, ch in enumerate(s):
            if ch.isdigit():
                num = num * 10 + int(ch)   # build multi-digit numbers

            if (not ch.isdigit() and ch != ' ') or i == len(s) - 1:
                # flush num using the PREVIOUS operator
                if   op == '+': stack.append(num)
                elif op == '-': stack.append(-num)
                elif op == '*': stack.append(stack.pop() * num)
                elif op == '/': stack.append(int(stack.pop() / num))   # truncate toward zero
                op, num = ch, 0           # save new operator, reset accumulator

        return sum(stack)
Key Interview Tips 面试要点
  • Initialize op = '+' so the first number is correctly pushed as a positive term
  • Apply the previous operator when you see the current operator or end-of-string
  • Use int(a / b), not a // b, for truncation toward zero with negative numbers
  • The stack accumulates independent additive terms — multiply/divide terms are resolved eagerly
  • Handle both the "operator character" trigger and the "last character" trigger in the same branch
