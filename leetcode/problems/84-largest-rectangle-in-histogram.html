Largest Rectangle in Histogram
Hard Monotonic Stack
Problem Statement

Given an array heights representing the heights of histogram bars (each bar has width 1), return the area of the largest rectangle that can be formed within the histogram.

Example: heights = [2,1,5,6,2,3] → 10 (the rectangle spanning bars at index 2 and 3, height 5)

Stage 1 — Problem Introduction
IV
Interviewer
I've got a geometry problem for you. Imagine a bar chart — you have an array of non-negative integers representing bar heights, and every bar has width 1. Your task is to find the area of the largest rectangle you can draw that fits entirely within those bars. For example, with [2,1,5,6,2,3] the answer is 10. Take a moment to make sure you understand what we're looking for before jumping in.
Me
Candidate
Got it. The rectangle must be axis-aligned, and its height is bounded by the shortest bar it spans. So a rectangle spanning multiple bars can only be as tall as the minimum bar in that range. Let me ask a few things to sharpen the constraints.
Stage 2 — Clarifying Questions
Me
Candidate
1. Can heights be zero? Like an empty column?
2. What's the range for n and for individual heights? I want to know if overflow is a concern.
3. If all bars are height 0, should I return 0?
4. Is it guaranteed that there's at least one bar?
IV
Interviewer
Heights are non-negative, so yes, zero is possible. n can be up to 105 and heights up to 104, so the max area fits in a 32-bit int but use 64-bit to be safe. Array is non-empty. And yes, all-zero input should give 0.
Stage 3 — Approach Discussion
Me
Candidate
Brute force: For every pair (i, j), the rectangle area is min(heights[i..j]) × (j−i+1). That's O(n²) pairs and O(n) to compute the min each time — O(n³) overall, or O(n²) with a running minimum. Too slow for n=10⁵.
The key observation: instead of thinking "what's the largest rectangle spanning bars i..j?", think "for each bar, what's the largest rectangle where THIS bar is the limiting height?" That rectangle extends as far left and right as possible while all bars are ≥ this height. If I know those boundaries for every bar, I'm done.
Me
Candidate

The insight is to flip the perspective: for each bar i, find the largest rectangle where bar i is the minimum. That rectangle extends left until we hit a bar shorter than heights[i], and right until the same. So I need, for each bar, the index of the nearest shorter bar on both sides.

A monotonic increasing stack gives me exactly this. I maintain a stack of indices whose heights are in increasing order. When I encounter a bar shorter than the top, that top bar's right boundary is the current index — I can compute its area. The new stack top becomes its left boundary.

I'll append a height-0 sentinel at the end to force all remaining bars to be popped and measured. Overall: O(n) time, O(n) space.

IV
Interviewer
Good. Why do you need the sentinel, and why do you seed the stack with -1 rather than leaving it empty?
Me
Candidate
The sentinel (height 0) is shorter than any real bar, so it triggers all remaining bars in the stack to be popped — without it, bars that were never "beaten" by a shorter bar to their right would never get their area computed. The -1 base in the stack acts as a left-boundary sentinel: when I compute width as i − stack[−1] − 1, the -1 gives the correct "no left boundary" case, extending the rectangle to the left edge.
Stage 4 — Pseudocode Walkthrough
Me
Candidate
Pseudocode
append 0 to heights          # sentinel forces final pop
stack = [-1]                 # left-boundary sentinel
max_area = 0

for i, h in enumerate(heights):
    while stack[-1] != -1 and heights[stack[-1]] >= h:
        height = heights[stack.pop()]
        width  = i - stack[-1] - 1  # new top is left boundary
        max_area = max(max_area, height * width)
    stack.append(i)

Tracing [2,1,5,6,2,3,0] (0 is sentinel):

  • i=0 h=2: stack=[-1,0]
  • i=1 h=1: 1<2 → pop 0: area=2×(1−(−1)−1)=2. 1 is not −1 done. stack=[-1,1]
  • i=2 h=5: stack=[-1,1,2]
  • i=3 h=6: stack=[-1,1,2,3]
  • i=4 h=2: pop 3: area=6×(4−2−1)=6. pop 2: area=5×(4−1−1)=10. max=10. stack=[-1,1,4]
  • i=5 h=3: stack=[-1,1,4,5]
  • i=6 h=0 (sentinel): pop 5: area=3×(6−4−1)=3. pop 4: area=2×(6−1−1)=8. pop 1: area=1×(6−(−1)−1)=6. done.
  • Return 10 ✓
IV
Interviewer
At i=4, you pop index 2 (height 5) and get width = 4−1−1 = 2. Walk me through why the width is 2 and not 3.
Me
Candidate
After popping index 2, the new stack top is index 1 (height 1). The formula is right − left − 1 = 4 − 1 − 1 = 2. The rectangle for height 5 can only span bars 2 and 3 — bar 1 has height 1 which is less than 5, so the boundary stops there. Width 2 × height 5 = 10. Correct.
Stage 5 — Complexity Analysis
Me
Candidate
Metric
Value
Reason
Time
O(n)
Each bar pushed and popped at most once — amortised O(1) per bar
Space
O(n)
Stack holds at most n indices in the worst case (monotone increasing input)

The amortised argument: even though the inner while loop can run many times on a single iteration, each index is pushed exactly once and popped exactly once across the entire algorithm. Total operations = 2n = O(n).

Stage 6 — Follow-up Questions
IV
Interviewer
Three follow-ups. First: how does this extend to finding the maximal rectangle in a binary matrix (LC #85)?
Me
Candidate
For each row of the matrix, treat it as the base of a histogram: height[j] is the number of consecutive 1s ending at that row in column j. Then run this exact algorithm on each row's histogram. Overall O(m×n) for an m×n matrix.
IV
Interviewer
Second: how does this compare mechanically to Trapping Rain Water (#42)?
Me
Candidate
Both use a monotonic stack and trigger computation when the order breaks, but the geometry is opposite. In #84, when a shorter bar pops a taller one, we measure the area above the ground extending outward. In #42, when a taller bar pops a shorter one in a valley, we measure the trapped water above the valley floor. Histogram: monotonic increasing stack. Rainwater: monotonic decreasing stack.
IV
Interviewer
Last one: could you solve this with divide and conquer? What's the complexity?
Me
Candidate
Yes — find the minimum bar in the current range (it becomes the height-limiter for any rectangle spanning the full range), then recurse on the left and right sub-ranges. The max rectangle is either: the full-width rectangle at the minimum height, or entirely within the left sub-range, or entirely within the right. With a segment tree for range-min queries: O(n log n) time. Without it, the worst case is O(n²) on a sorted array. Not competitive with the O(n) stack solution.

Full Python Solution

Python
def largestRectangleArea(heights):
    heights.append(0)   # sentinel — forces all remaining bars to be popped
    stack    = [-1]    # left-boundary sentinel
    max_area = 0

    for i, h in enumerate(heights):
        while stack[-1] != -1 and heights[stack[-1]] >= h:
            height = heights[stack.pop()]
            width  = i - stack[-1] - 1
            max_area = max(max_area, height * width)
        stack.append(i)

    heights.pop()   # restore original input
    return max_area
Key Interview Tips 💡
  • Always mention the sentinel 0 at the end — interviewers love asking why it's needed.
  • Seed the stack with [-1], not []; it acts as the left-boundary sentinel and avoids an empty-stack check inside the loop.
  • Width formula is right_index − new_stack_top − 1, not right − left. Practice the formula until it's automatic.
  • State the amortised O(n) argument explicitly: each index is pushed once and popped once → 2n operations total.
  • Know the connection to #85 Maximal Rectangle — it's the same algorithm applied row-by-row to a binary matrix.
  • This and #42 Trapping Rain Water are the two "must-master" hard monotonic stack problems. If you can explain both, you've covered the pattern fully.
