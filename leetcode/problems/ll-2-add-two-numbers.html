Add Two Numbers
Medium Simulation Linked List
Problem Statement

You are given two non-empty linked lists representing two non-negative integers. The digits are stored in reverse order, and each node contains a single digit. Add the two numbers and return the sum as a linked list.

You may assume the two numbers do not contain any leading zero, except the number 0 itself.

EXAMPLE
Input:  l1 = 2 → 4 → 3  (represents 342),  l2 = 5 → 6 → 4  (represents 465)
Output: 7 → 0 → 8  (represents 807, because 342 + 465 = 807)

Because the digits are stored in reverse order, the ones digit comes first — this means we can add left-to-right, exactly as grade-school addition works with carry.

Stage 3 — Approach Discussion
Me
Candidate
Let me think about approaches:

Naive approach — convert to integers: Walk each list to reconstruct the integers, add them, then convert the sum back to a linked list. This works, but is artificial — it throws away the structure of the problem and doesn't translate to languages without big integers.

Optimal — direct simulation: Walk both lists simultaneously, digit by digit. At each position, compute total = l1.val + l2.val + carry. The new node's digit is total % 10 and the carry forwarded is total // 10. When one list runs out, treat its contribution as 0. Continue as long as either list still has nodes or carry is non-zero (to handle that final overflow case).

I'll use a dummy head node so I never need to special-case the first node — the same pattern I'd use for any linked-list construction.
Dummy head is the key ergonomic trick here. Without it, I'd have to check "is this the first node?" on every iteration. With it: just do cur.next = ListNode(digit) and cur = cur.next every time. Return dummy.next at the end. The carry loop condition — "while l1 or l2 or carry" — neatly handles all three termination cases in one line.

Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode:
Pseudocode
function addTwoNumbers(l1, l2):
    dummy = ListNode(0)     # sentinel head
    cur   = dummy
    carry = 0

    while l1 or l2 or carry:
        val = carry
        if l1:
            val += l1.val
            l1  = l1.next
        if l2:
            val += l2.val
            l2  = l2.next
        carry, digit = divmod(val, 10)   # carry = val // 10, digit = val % 10
        cur.next = ListNode(digit)
        cur      = cur.next

    return dummy.next

Stage 5 — Complexity Analysis
Me
Candidate
Time: O(max(m, n)) where m and n are the lengths of the two lists. We process each position at most once, and at most one extra iteration for a final carry.

Space: O(max(m, n)) for the output list. The result has at most max(m, n) + 1 nodes. We use only a constant number of extra variables (carry, val, cur) — so auxiliary space is O(1), but the output itself is O(max(m, n)).

Stage 6 — Follow-up Questions
IV
Interviewer
What if the digits were stored in forward order — most significant digit first — instead of reversed?
Me
Candidate
That's LeetCode #445. The challenge is that carry propagates right-to-left, but we're traversing left-to-right. Three options: reverse both input lists first (then apply this exact algorithm, then reverse the result); use stacks to process digits from the end without modifying inputs; or use recursion to reach the tail first and propagate carry on the way back up. Reversing is the simplest — it reuses this solution directly.
IV
Interviewer
What's the maximum number length this solution can handle?
Me
Candidate
In Python, integers have arbitrary precision, so there's no overflow concern — this solution handles lists of any length limited only by memory. In Java or C++, you'd need to be careful: using int for the carry is fine since carry is always 0 or 1, but if you tried the "convert to integer" approach instead, you'd overflow a 64-bit integer for lists longer than about 19 nodes. The simulation approach is actually better than the conversion approach precisely because it avoids overflow entirely.
IV
Interviewer
What if the numbers could be negative?
Me
Candidate
I'd handle the sign separately. Determine the sign of each number from a leading sign node or a separate flag. If both are the same sign, add the magnitudes and apply the shared sign to the result. If they differ, subtract the smaller magnitude from the larger and apply the sign of the larger. The digit-by-digit traversal logic can be adapted for subtraction with borrowing, though it's more complex — or you could just convert to integers, do the signed arithmetic, and reconstruct.

✅ Full Python Solution

Python 3 — Add Two Numbers O(max(m,n)) time · O(max(m,n)) space 
class Solution:
    def addTwoNumbers(self, l1: Optional[ListNode], l2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        cur   = dummy
        carry = 0

        while l1 or l2 or carry:
            val = carry
            if l1:
                val += l1.val
                l1   = l1.next
            if l2:
                val += l2.val
                l2   = l2.next
            carry, digit = divmod(val, 10)
            cur.next = ListNode(digit)
            cur      = cur.next

        return dummy.next
Key Interview Tips 💡
  • The reversed storage order is a gift — it means head = ones digit, so you can add left-to-right without any reversal.
  • The loop condition while l1 or l2 or carry handles unequal lengths and a final overflow carry in one clause.
  • Use a dummy head node — it removes the need to special-case constructing the first output node.
  • divmod(val, 10) gives (carry, digit) in one call — clean and readable.
  • Start val = carry (not 0) so the carry from the previous step is automatically included.
  • If asked about forward-order digits (LC #445), mention: reverse both lists, apply this algorithm, reverse the result.
