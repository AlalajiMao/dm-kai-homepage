Next Greater Element I
Medium Monotonic Stack Hash Map
Problem Statement

You are given two integer arrays nums1 and nums2, where nums1 is a subset of nums2. For each element in nums1, find the next greater element in nums2 — the first element to its right in nums2 that is strictly greater. If no such element exists, return -1 for that position.

EXAMPLES
nums1 = [4,1,2], nums2 = [1,3,4,2] → [-1,3,-1]
nums1 = [2,4], nums2 = [1,2,3,4] → [3,-1]

Stage 3 — Approach Discussion
Me
Candidate
Let me walk through the progression of solutions.

Brute force O(m×n): For each element in nums1, find its position in nums2, then scan rightward until I find a larger value. Works, but repeats work for each query.

Optimal O(m+n): The key insight is to decouple the two steps. First, precompute the "next greater element" for every value in nums2 using a monotonic stack and store the results in a hash map. Then answer each nums1 query in O(1) with a simple lookup.

The monotonic stack works like this: I maintain a decreasing stack of values seen so far. When a new value arrives that is larger than the stack top, that new value is the "next greater" answer for everything it beats on the stack — so I pop those off and record them in the map. Anything still on the stack at the end has no greater element to its right, so it maps to -1.
The monotonic stack invariant: elements on the stack are in decreasing order. A new larger element "resolves" all smaller waiting elements at once. Each element is pushed once and popped once — amortized O(1) per element, O(n) overall.
IV
Interviewer
Good. Trace through nums2 = [1, 3, 4, 2] with the monotonic stack.
Me
Candidate
Starting with stack=[], nge={}.

See 1: stack empty, push. Stack: [1].
See 3: 3 > 1 → pop 1, record nge[1]=3. Stack empty, push 3. Stack: [3].
See 4: 4 > 3 → pop 3, record nge[3]=4. Stack empty, push 4. Stack: [4].
See 2: 2 < 4 → just push. Stack: [4, 2].
Drain: pop 2 → nge[2]=-1. Pop 4 → nge[4]=-1.

Final map: {1:3, 3:4, 4:-1, 2:-1}.
If nums1 = [4,1,2]: return [nge[4], nge[1], nge[2]] = [-1, 3, -1] ✅
Stage 4 — Pseudocode & Code
Me
Candidate
The pseudocode is very clean — two phases, then a lookup:
Pseudocode
function nextGreaterElement(nums1, nums2):
    nge   = {}          # value → next greater element
    stack = []          # monotonically decreasing stack of values

    # Phase 1: precompute next greater for every element in nums2
    for num in nums2:
        while stack and stack[-1] < num:
            nge[stack.pop()] = num   # num is the next greater for the popped value
        stack.push(num)

    # Drain: remaining stack values have no next greater element
    while stack:
        nge[stack.pop()] = -1

    # Phase 2: look up each nums1 query in O(1)
    return [nge[n] for n in nums1]

If there were duplicate values, I'd need to store indices instead, and the map would key by index rather than value. But for this problem, values as keys is cleaner.

Stage 5 — Complexity Analysis
Me
Candidate
Let n = len(nums2), m = len(nums1).

Time: O(n + m). The monotonic stack processes nums2 in O(n) — each element is pushed once and popped at most once, so all the inner while iterations together are still O(n) amortized. The final lookup over nums1 is O(m).

Space: O(n) for the hash map (one entry per element of nums2) and O(n) for the stack in the worst case (a strictly decreasing nums2 like [4,3,2,1] where nothing gets popped during traversal).

Stage 6 — Follow-up Questions
IV
Interviewer
Three follow-ups: (1) What if nums2 were a circular array — wrapping around? (2) What if we wanted the previous smaller element instead? (3) Can you explain the amortized O(n) argument more carefully?
Me
Candidate
(1) Circular array — #503 Next Greater Element II: Iterate through nums2 twice (or use i % n indices up to 2n). On the second pass, elements that were waiting on the stack finally get their answers from the "wrapped around" part of the array. The stack logic is identical — just double the loop range.

(2) Previous smaller element: Same monotonic stack technique, just traversed from right to left instead of left to right, and we pop when the incoming value is greater than the stack top (maintaining an increasing stack). Alternatively, traverse left-to-right but flip the comparison operator. These four variants — next/previous, greater/smaller — all follow the same template.

(3) Amortized O(n): The key argument is that each element is pushed onto the stack exactly once and popped at most once. The total number of push operations across the entire loop is n, and the total number of pop operations (across all iterations of the inner while) is also at most n. So even though any single iteration could pop multiple elements, the total work over all iterations is bounded by 2n — that's O(n) amortized, not O(n²).

✅ Full Python Solution

Python 3 — Next Greater Element I O(n + m) time · O(n) space 
class Solution:
    def nextGreaterElement(self, nums1: list[int], nums2: list[int]) -> list[int]:
        nge: dict[int, int] = {}   # value → next greater element in nums2
        stack: list[int] = []       # monotonically decreasing stack (values)

        for num in nums2:
            while stack and stack[-1] < num:
                nge[stack.pop()] = num    # num is the answer for popped elements
            stack.append(num)

        while stack:                     # no greater element exists to the right
            nge[stack.pop()] = -1

        return [nge[n] for n in nums1]
Key Interview Tips 面试要点
  • Build the map on nums2 first — query nums1 second. Never mix the two loops.
  • Push values (not indices) since all values are distinct — avoids a needless nums2[i] indirection
  • Always drain the remaining stack with -1 — forgetting this is the most common bug
  • Amortized O(n): each element is pushed once and popped at most once — total ops ≤ 2n
  • This is the warm-up for #503 (circular) and #739 (index distances) — know all three variants
