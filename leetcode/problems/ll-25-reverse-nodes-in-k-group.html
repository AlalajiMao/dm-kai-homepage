Reverse Nodes in k-Group
Hard In-place Reversal Linked List
Problem Statement

Given the head of a linked list, reverse the nodes of the list k at a time, and return the modified list.

k is a positive integer and is less than or equal to the length of the linked list. If the number of nodes is not a multiple of k then the left-out nodes at the end should remain as they are.

You may not alter the values in the list's nodes, only the nodes themselves may be changed.

EXAMPLES
Input: 1→2→3→4→5, k=2   Output: 2→1→4→3→5
Input: 1→2→3→4→5, k=3   Output: 3→2→1→4→5

Groups of k are reversed in place. The final group (fewer than k nodes) is left untouched.

💬 Mock Interview

This problem builds directly on #206 (reverse a full list) and #92 (reverse a subrange). The key insight is the front-insert reversal technique: repeatedly pull the node immediately after cur and insert it at the front of the group, k-1 times. A dummy head and careful pointer bookkeeping keep this O(1) extra space.

The challenge is: after reversing a group, I need to correctly connect it to the previous group and to the next group, which hasn't been reversed yet. A dummy head will simplify those connections.

Stage 3 — Approach Discussion
Me
Candidate
Two approaches:

Recursive: Reverse k nodes, recursively reverse the rest, and connect. Clean to reason about but uses O(n/k) stack frames — not O(1) space.

Iterative with front-insert (O(1) space): Use a dummy head and a pre pointer tracking the node just before the current group. For each group:
  1. Check if k nodes remain (walk k steps; if not, stop).
  2. Reverse the k nodes in place using front-insert: k-1 times, pull the node right after cur and insert it right after pre.
  3. After reversal, cur (original group head) is now the tail — advance pre to cur.
Front-insert in a group: pre→[A→B→C→D] rest. We want [C→B→A→D]. Iteration 1: pull B, insert after pre: pre→B→A→C→D. Wait — let me re-think. With cur=A, we do k-1 iterations: each time pull cur.next and place it at pre.next. Iter 1: nxt=B, B.next=A (pre.next), pre.next=B → pre→B→A→C→D, cur=A. Iter 2: nxt=C, C.next=B (pre.next), pre.next=C → pre→C→B→A→D, cur=A. Done! cur (A) is now the tail. Advance pre=cur=A for next group.
Me
Candidate
I'll go with the iterative front-insert approach — O(1) space, no recursion limit concerns.

Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode:
Pseudocode
function reverseKGroup(head, k):
    dummy = ListNode(0, head)
    pre   = dummy

    while True:
        # 1. Check if k nodes remain
        check = pre
        for _ in range(k):
            check = check.next
            if not check: return dummy.next   # fewer than k nodes left

        # 2. Reverse k nodes starting from pre.next
        cur = pre.next
        for _ in range(k - 1):
            nxt      = cur.next
            cur.next = nxt.next      # cut nxt out
            nxt.next = pre.next      # nxt points to current front
            pre.next = nxt           # insert nxt at front of group

        # 3. cur is now the tail of the reversed group
        pre = cur
Me
Candidate
Tracing dummy→1→2→3→4→5, k=2. pre=dummy.

cur=1. Run k-1=1 iteration of the inner loop:

  List: dummy→2→1→3→4→5
pre = cur = 1 (node 1 is now the tail of group 1).

Group 2 check: walk 2 steps from pre(=node 1): reach node 4. Not null — proceed.
cur=3. Run k-1=1 iteration:
  nxt=4, cur(3).next=5, nxt(4).next=3 (pre.next), pre.next=4

pre = cur = 3 (node 3 is now tail of group 2).

Group 3 check: walk 2 steps from pre(=node 3): first step reaches 5, second step reaches null. Return dummy.next = 2.

IV
Interviewer
Clear trace. What does cur represent before and after reversing each group?
Me
Candidate
Before the inner loop, cur = pre.next — it is the head of the current group (the first node to be reversed). After the inner loop, because we insert nodes in front of it, all k-1 other nodes in the group have been moved ahead of it — making cur the tail of the reversed group. That's why we set pre = cur: we advance pre to the tail of the current group, ready to be the anchor for the next group's reversal.
Stage 5 — Complexity Analysis
Me
Candidate
Time: O(n) — each node is visited at most twice: once during the k-step check, and once during the k-1 inner loop reversals. Total work per node is O(1) amortized.

Space: O(1) — only the dummy node and a constant number of pointer variables. No recursion, no extra storage.

Stage 6 — Follow-up Questions
IV
Interviewer
What happens when k=1 or k equals the list length?
Me
Candidate
k=1: the inner loop runs k-1=0 times — no nodes are moved. The check advances one step per iteration, pre advances one node per group, and the list is returned unchanged. Correct.

k=n (full list length): the check succeeds once, we reverse all n nodes in one group, then the next check walk finds null immediately and we return. Equivalent to a full list reversal.
IV
Interviewer
Could you implement a recursive version? What's the trade-off?
Me
Candidate
Yes. Recursive approach: check if k nodes remain; if not, return head. Otherwise, reverse k nodes, then recursively call on the remaining list and wire the result to the tail of the current reversed group. The code is arguably more readable — each call handles exactly one group. But it uses O(n/k) stack frames, which for k=1 is O(n) — potentially hitting recursion limits on very long lists. The iterative solution is strictly better on space.
IV
Interviewer
How would you reverse from the end instead of the beginning?
Me
Candidate
That's trickier. I'd first compute the list length L. Then the first group to reverse starts at position L mod k (since we want full groups from the end). I'd skip the initial partial group, then apply the same iterative reversal to the remaining full groups. Alternatively, reverse the whole list, apply the k-group reversal, then reverse the full result again — but that reverses the group ordering. The length-computation approach is cleaner.

✅ Full Python Solution

Python 3 — Reverse Nodes in k-Group O(n) time · O(1) space 
class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        pre   = dummy

        while True:
            # Check if k nodes remain
            check = pre
            for _ in range(k):
                check = check.next
                if not check:
                    return dummy.next

            # Reverse k nodes starting from pre.next (front-insert technique)
            cur = pre.next
            for _ in range(k - 1):
                nxt      = cur.next
                cur.next = nxt.next
                nxt.next = pre.next
                pre.next = nxt

            pre = cur  # cur is now the tail of the reversed group
Key Interview Tips 💡
  • Always verify k nodes remain before reversing — walk k steps from pre and check for null at each step.
  • The front-insert reversal: cur (the original group head) stays fixed; you insert nodes in front of it one by one. After k-1 inserts, cur is the tail.
  • Use a dummy head so pre always has a valid previous node, even for the very first group.
  • After reversing a group, set pre = cur — cur is now the tail of the just-reversed group and the anchor for the next group.
  • k=1 (no change) and k=n (full reversal) both work without special casing — verify this in your head before submitting.
