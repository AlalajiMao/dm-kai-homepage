Sum of Subarray Minimums
Medium Monotonic Stack
Problem Statement

Given an array of integers arr, find the sum of min(b) for every contiguous subarray b of arr. Return the answer modulo 109 + 7.

EXAMPLE
Input: arr = [3, 1, 2, 4]
Output: 17

Subarrays and their minimums:
[3]→3, [1]→1, [2]→2, [4]→4, [3,1]→1, [1,2]→1, [2,4]→2, [3,1,2]→1, [1,2,4]→1, [3,1,2,4]→1
Sum = 3+1+2+4+1+1+2+1+1+1 = 17

💬 Mock Interview

This problem looks like a nested loop problem at first glance, but the key unlock is contribution counting: instead of enumerating subarrays, ask "how many subarrays is each element the minimum of?" A monotonic stack answers that in O(n). （贡献法 + 单调栈）

Me

A few quick questions:

  • What's the array size — roughly 104 or 105?
  • Is the modulo only applied at the end, or do I need intermediate mod as well?

Stage 3 — Approach Discussion
Me
Candidate
The brute force approach: iterate over all O(n²) subarrays, find the minimum of each. If I track a running minimum while expanding the right boundary, that's O(n²) time and O(1) extra space. For n=30,000 that's 9×108 operations — too slow.
IV
Interviewer
Agreed. How would you approach the O(n) solution?
Instead of asking "what is the minimum of each subarray?", flip the question: "for each element arr[i], in how many subarrays is it the minimum?" If arr[i] is the minimum of exactly C subarrays, its total contribution to the answer is arr[i] * C. To count C, I need to know how far left and right I can extend while arr[i] remains the minimum. That means finding the nearest smaller element on each side — a textbook monotonic stack job.
Me
Candidate
The key insight is contribution counting. Rather than iterating subarrays, I ask: for each element arr[i], how many subarrays have it as the minimum? If I know that, its contribution to the total is arr[i] * count.

To find the count, I define:
  • left[i] = distance to the previous element that is strictly smaller than arr[i] (or left boundary if none). This is how far left a subarray starting at position i can extend while arr[i] remains the minimum.
  • right[i] = distance to the next element that is smaller or equal to arr[i] (or right boundary if none). This is how far right it can extend.

Then the number of subarrays where arr[i] is the minimum is left[i] * right[i], so arr[i]'s contribution is arr[i] * left[i] * right[i].
IV
Interviewer
Why do you use strictly smaller on the left but smaller-or-equal on the right?
Me
Candidate
This is the double-counting trap with duplicates. If arr = [2, 2] and we used strictly smaller on both sides, both elements would claim the subarray [2, 2] as their contribution. By being asymmetric — strictly smaller on the left, smaller-or-equal on the right — each subarray is assigned to exactly one element as its "owner". Specifically, when there are duplicates, the leftmost one wins.
IV
Interviewer
Good. And how do you compute left[i] and right[i] efficiently?
Me
Candidate
With a monotonic stack — two separate passes:
  • Left pass (left to right): maintain a stack of indices with increasing values. For each i, pop while arr[stack[-1]] >= arr[i]. If stack is empty, left[i] = i + 1; otherwise left[i] = i - stack[-1]. Push i.
  • Right pass (right to left): same idea but pop while arr[stack[-1]] > arr[i] (strictly greater, to keep the asymmetry). If stack is empty, right[i] = n - i; otherwise right[i] = stack[-1] - i. Push i.
Both passes are O(n) by the same amortised argument as Daily Temperatures.

Pseudocode — Contribution Counting with Monotonic Stack
function sumSubarrayMins(arr):
    MOD   = 10**9 + 7
    n     = len(arr)
    left  = [0] * n   # distance to previous strictly-smaller element
    right = [0] * n   # distance to next smaller-or-equal element
    stack = []

    # Left pass: pop while top >= current (strict on left)
    for i in range(n):
        while stack and arr[stack[-1]] >= arr[i]:
            stack.pop()
        left[i] = i + 1 if not stack else i - stack[-1]
        stack.append(i)

    stack = []
    # Right pass: pop while top > current (strict on right)
    for i in range(n - 1, -1, -1):
        while stack and arr[stack[-1]] > arr[i]:
            stack.pop()
        right[i] = n - i if not stack else stack[-1] - i
        stack.append(i)

    return sum(arr[i] * left[i] * right[i] for i in range(n)) % MOD

Stage 6 — Follow-up Questions
IV
Interviewer
What would change if you needed the sum of subarray maximums instead of minimums?
Me
Candidate
The algorithm is identical, just flip the comparisons. Instead of "previous strictly smaller" and "next smaller-or-equal", you look for "previous strictly larger" and "next larger-or-equal". That is, the stack now stays decreasing instead of increasing. The contribution formula remains arr[i] * left[i] * right[i].
IV
Interviewer
If someone suggested using a single pass with the stack instead of two passes, is that possible?
Me
Candidate
Yes — when you pop an element during the single left-to-right pass, you already know both its left and right boundaries at that moment: the new stack top is the left boundary, and the current index is the right boundary. You can compute the contribution inline when you pop. This eliminates the left and right arrays entirely, reducing space slightly. The two-pass version is easier to reason about and explain in an interview, so I'd present that first, then offer the single-pass as an optimisation.
IV
Interviewer
How would you extend this to the sum of subarray ranges — max minus min for each subarray?
Me
Candidate
Since sum of ranges = sum of maxes − sum of mins, and both are linear, you'd compute them independently using the two approaches above and subtract. The time and space complexity stays O(n). Be careful to apply the modulo consistently — the subtraction might produce a negative number mod M, so add M before taking mod: (sum_max - sum_min + MOD) % MOD.

✅ Full Python Solution

Python 3 — Sum of Subarray Minimums O(n) time · O(n) space 
class Solution:
    def sumSubarrayMins(self, arr: list[int]) -> int:
        MOD   = 10**9 + 7
        n     = len(arr)
        left  = [0] * n
        right = [0] * n
        stack = []

        # Left pass: previous strictly-smaller element
        for i in range(n):
            while stack and arr[stack[-1]] >= arr[i]:
                stack.pop()
            left[i] = i + 1 if not stack else i - stack[-1]
            stack.append(i)

        stack = []

        # Right pass: next smaller-or-equal element (asymmetric to avoid double-counting)
        for i in range(n - 1, -1, -1):
            while stack and arr[stack[-1]] > arr[i]:
                stack.pop()
            right[i] = n - i if not stack else stack[-1] - i
            stack.append(i)

        return sum(arr[i] * left[i] * right[i] for i in range(n)) % MOD
Key Interview Tips 面试要点
  • Flip the question: don't iterate over subarrays — iterate over elements and count how many subarrays each element owns
  • Asymmetric comparison (>= on left, > on right) is the critical detail for duplicates — say this out loud in the interview
  • Modulo placement: apply to the final sum; if subtracting two mod results, add MOD before taking mod to avoid negatives
  • Know the single-pass optimisation but present the two-pass version first for clarity
  • This pattern directly extends to sum of subarray maxes and sum of subarray ranges
