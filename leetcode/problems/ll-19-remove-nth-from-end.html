Remove Nth Node From End of List
Medium Dummy Head + Two Pointers Linked List
Problem Statement

Given the head of a linked list, remove the n-th node from the end of the list and return its head.

EXAMPLES
Input: 1 → 2 → 3 → 4 → 5, n=2  →  Output: 1 → 2 → 3 → 5
Input: 1, n=1  →  Output: []

For the first example, the 2nd node from the end is node 4 (1-indexed from the tail). Removing it yields 1 → 2 → 3 → 5. The second example removes the only node, returning an empty list.

💬 Mock Interview

A realistic interview dialogue covering the dummy-head trick, the n+1 gap nuance, and why this pattern handles removing the head node cleanly.

Stage 1 — Problem Introduction
IV
Interviewer
Given a linked list and an integer n, remove the n-th node from the end and return the head. Can you do it in one pass?
Me
Candidate
Yes — this is a classic two-pointer gap problem. The key insight is that if I keep two pointers separated by exactly n nodes, when the front pointer reaches the end, the back pointer is sitting at the n-th node from the end. I can then do the deletion. But there's an important edge case I want to nail: removing the head node itself.
Stage 2 — Clarifying Questions
Me
Candidate
A few things I want to confirm:
  • Is n guaranteed to be valid — i.e., 1 ≤ n ≤ list length?
  • Can n equal the length of the list, meaning we remove the head?
  • Is this a singly linked list with no tail pointer?
IV
Interviewer
Yes — n is always valid. Yes — n can equal the list length (removing the head). Singly linked list. The constraints are: 1 ≤ n ≤ sz ≤ 30, and node values are 0–100.
Stage 3 — Approach Discussion
Me
Candidate
Brute force — two passes: First traverse to count the total length L. Then traverse again to the (L − n)th node (0-indexed), which is the predecessor of our target. Set predecessor.next = predecessor.next.next. Simple but two passes.

Optimal — one pass with a dummy head and gap of n+1:
I'll prepend a dummy node before head. Both fast and slow start at dummy.
Advance fast exactly n+1 steps (not n!). Then advance both until fast is None.
Now slow is the predecessor of the target. Execute the deletion.
Return dummy.next (handles the case where head was removed).
Why n+1 and not n? I need slow to stop at the PREDECESSOR (the node just before the target), not at the target itself, because I need to rewire slow.next to skip the target. Moving fast n+1 steps creates a gap of n+1 between fast and slow, so when fast is None (off the end), slow is n+1 steps behind — at the predecessor. If I used n steps, slow would land ON the target, not before it.
Me
Candidate
The dummy node is the other critical piece. Without it, removing the head node requires a special case — there's no predecessor to rewire. With the dummy as a sentinel predecessor, the general case handles head removal automatically: slow stays at dummy, and dummy.next = dummy.next.next skips the original head.
IV
Interviewer
Good. Walk me through the code.
Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode:
Pseudocode
function removeNthFromEnd(head, n):
    dummy = ListNode(0, head)       # sentinel before head
    fast = slow = dummy

    for _ in range(n + 1):           # advance fast n+1 steps
        fast = fast.next

    while fast:                       # move both until fast falls off
        fast = fast.next
        slow = slow.next

    # slow is now the predecessor of the target
    slow.next = slow.next.next        # skip the target node

    return dummy.next                 # head may have changed
Me
Candidate
Let me trace through 1 → 2 → 3 → 4 → 5, n=2.

Setup: dummy → 1 → 2 → 3 → 4 → 5
fast=dummy, slow=dummy

Advance fast n+1 = 3 steps:
Step 1: fast → node[1]
Step 2: fast → node[2]
Step 3: fast → node[3]
After loop: fast=node[3], slow=dummy

Move both until fast is None:
Iteration 1: fast=node[4], slow=node[1]
Iteration 2: fast=node[5], slow=node[2]
Iteration 3: fast=None, slow=node[3]
Loop ends.

Delete: slow=node[3]. slow.next=node[4]. slow.next.next=node[5].
Set slow.next = node[5] → node[3] now points directly to node[5]. Node[4] is removed.
Result: 1 → 2 → 3 → 5 ✅
Return dummy.next = node[1] ✅
IV
Interviewer
Good. Now trace through the edge case: a single-node list [1] with n=1.
Me
Candidate
Setup: dummy → 1 → None
fast=dummy, slow=dummy

Advance fast n+1 = 2 steps:
Step 1: fast → node[1]
Step 2: fast → None

While fast loop: fast is already None → loop body never runs.
slow stays at dummy.

Delete: slow=dummy. slow.next=node[1]. slow.next.next=None.
Set dummy.next = None. Node[1] is unlinked.
Return dummy.next = None ✅ (empty list)
IV
Interviewer
Perfect. That's exactly the head-removal case working cleanly through the dummy.

Space: O(1) — only the dummy node and two pointer variables. No recursion, no auxiliary storage.

Stage 6 — Follow-up Questions
IV
Interviewer
Why is the dummy node necessary here? Couldn't you just handle the head case with an if-statement?
Me
Candidate
Technically yes — you could check at the end whether n equals the list length and if so return head.next. But the dummy node is cleaner: it eliminates the special case entirely and keeps the logic uniform. The dummy acts as a sentinel predecessor for the head node, so the same "slow.next = slow.next.next" code works regardless of which node is being deleted. In production code and in interviews, preferring uniform logic over branching is usually better style.
IV
Interviewer
How would you solve this if you didn't know the list length in advance and wanted to use two passes instead?
Me
Candidate
First pass: traverse the whole list, count the length L.
Second pass: advance to the (L − n)th node (1-indexed from the start), which is the predecessor. Then do slow.next = slow.next.next.

Again, a dummy node at the front simplifies the predecessor logic — if L − n is 0, the dummy is the predecessor and we remove the original head by returning dummy.next.
IV
Interviewer
One more: what changes if this were a doubly linked list?
Me
Candidate
With a doubly linked list, you can traverse backwards — so you could just walk n steps back from the tail to find the target node directly, then unlink it by updating both its predecessor's next and its successor's prev. You wouldn't need the two-pointer gap trick at all. That's one of the main practical advantages of doubly linked lists over singly linked ones.

✅ Full Python Solution

Python 3 O(n) time · O(1) space 
class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        fast = slow = dummy

        for _ in range(n + 1):        # advance fast n+1 steps from dummy
            fast = fast.next

        while fast:                    # move both until fast is None
            fast = fast.next
            slow = slow.next

        slow.next = slow.next.next     # unlink the target node
        return dummy.next              # return real head (may have changed)
Key Interview Tips 💡
  • n+1, not n: You need slow to stop at the predecessor so you can rewire. This off-by-one is the most common mistake — always verify with a trace.
  • Dummy node is non-negotiable: Without it, removing the head requires a special-case branch. The dummy eliminates that entirely — use it any time you might delete the head.
  • Return dummy.next, not head — when the original head is removed, head is stale but dummy.next always points to the real new head.
  • The two-pointer gap pattern generalises: "find the k-th from end" problems all use the same setup with different gap sizes.
  • Always trace both a middle-node removal and a head-node removal in your explanation — it proves you understand the edge cases.
