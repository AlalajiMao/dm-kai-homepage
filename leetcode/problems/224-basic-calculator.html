Basic Calculator
Hard Expression Eval
Problem Statement

Given a string s representing a mathematical expression containing digits, '+', '-', '(', ')', and spaces, implement a basic calculator to evaluate it and return the result.

Examples:

  • "1 + 1" → 2
  • " 2-1 + 2 " → 3
  • "(1+(4+5+2)-3)+(6+8)" → 23

No multiplication or division. The expression is always valid.

Stage 3 — Approach Discussion
Me
Candidate
Brute force / recursive: Find the innermost parentheses, evaluate them, replace with the number, and repeat. That's O(n²) in the worst case due to repeated string scanning, and awkward to implement cleanly.
The key insight: when I see an opening parenthesis, I'm starting a new "sub-expression." Everything I've computed so far — the running result and the sign in front of the parenthesis — needs to be saved somewhere so I can restore it after the closing paren. That's exactly what a stack does. The stack saves context; I reset and solve the inner expression as if it's a fresh problem.
Me
Candidate

The efficient approach tracks three things as I scan left to right: result (running total for the current level), num (the digit accumulator for multi-digit numbers), and sign (+1 or −1).

  • Digit: accumulate into num (handles multi-digit).
  • +/−: flush num into result with current sign, update sign.
  • (: push (result, sign) onto the stack — this freezes the outer context. Reset both to start fresh inside the parentheses.
  • ): flush the last num, then pop sign and outer result from the stack and merge: result = outer_result + saved_sign × inner_result.

This is O(n) time and O(n) space — one pass, stack depth proportional to nesting.

IV
Interviewer
How does the unary minus case work — say the input is -(3+2)? Walk me through it.
Me
Candidate
When we see - we set sign = −1. Then we see (: push (result=0, sign=−1) and reset. Inside we compute 3+2=5. When we hit ) we pop sign=−1 and outer_result=0: final = 0 + (−1)×5 = −5. The sign in front of the parenthesis is correctly captured in the stack and applied when we close it.
Stage 4 — Pseudocode Walkthrough
Me
Candidate
Pseudocode
stack = [], result = 0, num = 0, sign = 1

for ch in s:
    if ch.isdigit():  num = num*10 + int(ch)
    elif ch == '+': result += sign*num; num=0; sign=1
    elif ch == '-': result += sign*num; num=0; sign=-1
    elif ch == '(':
        stack.push(result); stack.push(sign)   # freeze outer context
        result=0; sign=1                       # fresh start inside
    elif ch == ')':
        result += sign*num; num=0
        result *= stack.pop()                    # apply sign before '('
        result += stack.pop()                    # restore outer result

return result + sign*num

Trace "1+(2-3)":

  • '1' → num=1
  • '+' → result=1, num=0, sign=+1
  • '(' → push 1, push +1. result=0, sign=+1
  • '2' → num=2
  • '-' → result=2, num=0, sign=−1
  • '3' → num=3
  • ')' → result += −1×3 = −1. result×=pop(+1)=−1. result+=pop(1)=0
  • return 0 + 1×0 = 0 ✓
IV
Interviewer
Why do you push result first and then sign, rather than the other way around?
Me
Candidate
Because we pop in reverse order on ). We first pop the sign (multiply by it) and then pop the outer result (add to it). Since Python's stack is LIFO, pushing result first means it's at the bottom, popped second — which is exactly what we want. It's easy to get the order backwards, so I always remind myself: "push result, push sign — pop sign, pop result."

Stage 6 — Follow-up Questions
IV
Interviewer
How would you extend this to also handle multiplication and division (#227 Basic Calculator II)?
Me
Candidate
For * and /, we need to handle operator precedence. The trick: for + and −, push the signed number onto the stack. For * and /, pop the top, compute, push back. This resolves * and / immediately (higher precedence) while + and − accumulate. Sum the stack at the end. Combining both — parentheses plus all four operators — gives the full #772 Basic Calculator III, which needs careful interleaving of both techniques.
IV
Interviewer
What if we need to evaluate expressions with variables, like "a + b * (c - d)" where variable values are given separately?
Me
Candidate
Same structure — pass in a variables dictionary. When we encounter a sequence of letters instead of digits, look up the variable in the dictionary to get its numeric value. The rest of the algorithm is identical. Edge cases: variable names can be multi-character, so accumulate letters just like we accumulate digits for multi-digit numbers.
IV
Interviewer
Nice. One last thing — can this be done recursively instead of iteratively?
Me
Candidate
Yes — whenever we see (, recurse with the rest of the string and return both the inner result and where parsing stopped. The call stack replaces the explicit stack. Same O(n) complexity, but Python's recursion depth limit could be an issue for deeply nested expressions. The iterative version is more robust in practice.

Full Python Solution

Python
def calculate(s: str) -> int:
    stack  = []
    result = 0
    num    = 0
    sign   = 1   # +1 or -1; initialised to + so leading numbers are added

    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)         # accumulate multi-digit number
        elif ch == '+':
            result += sign * num
            num, sign = 0, 1
        elif ch == '-':
            result += sign * num
            num, sign = 0, -1
        elif ch == '(':
            stack.append(result)   # push outer result first
            stack.append(sign)     # push sign in front of '(' second
            result, sign = 0, 1   # fresh context for inner expression
        elif ch == ')':
            result += sign * num   # flush last number inside parens
            num = 0
            result *= stack.pop()  # apply sign before '(' (popped first = pushed second)
            result += stack.pop()  # restore outer result (popped second = pushed first)
        # spaces: no action needed — isdigit() and the elif chain skip them

    return result + sign * num   # flush any trailing number
Key Interview Tips 💡
  • Initialise sign = 1 so the first number is correctly added to result.
  • Push order matters: push result first, then sign — so you pop sign first on ). Get this backwards and you'll produce wrong answers on nested expressions.
  • Always flush num into result before every (, +, -, and ) — and once more at the very end for the trailing number.
  • The result *= popped_sign line handles unary minus: e.g. -(3+2) pushes sign=−1, and on ) multiplies the inner result by −1.
  • Spaces are handled automatically — none of the elif branches match a space, so they're silently skipped.
  • This is the foundation for #772 Basic Calculator III. Once you master the parenthesis push/pop pattern here, adding * and / is a one-layer extension.
