Evaluate Reverse Polish Notation
Medium Stack Expression Evaluation Math
Problem Statement

Evaluate the value of an arithmetic expression in Reverse Polish Notation (postfix notation).

Valid operators are +, -, *, and /. Each operand may be an integer or another expression. Division between two integers truncates toward zero.

It is guaranteed the expression is valid. No division by zero will occur.

EXAMPLES
["2","1","+","3","*"] → 9 ((2+1)*3)
["4","13","5","/","+"] → 6 (4+(13/5))
["10","6","9","3","+","-11","*","/","*","17","+","5","+"] → 22

Stage 3 — Approach Discussion
Me
Candidate
The algorithm is clean. I iterate through each token:

— If it's a number, convert it to an integer and push it onto the stack.
— If it's an operator, pop two operands, apply the operator, and push the result back.

At the end, exactly one value remains on the stack — that's the answer.

The only subtlety is operand order for subtraction and division. When I pop, I get the second operand first, then the first. So if the stack looks like [..., a, b] and I see -, I pop b then a, and compute a - b, not b - a. I need to be careful to pop in the right order.
Mnemonic: "pop b first, then a" — b is on top because it was pushed last (it's the right operand). So the expression is always: a OP b, where a = second pop, b = first pop.
IV
Interviewer
You flagged the operand order issue preemptively — good. Does it matter for addition and multiplication?
Me
Candidate
For addition and multiplication, no — both are commutative, so a + b == b + a and a * b == b * a. Order only matters for subtraction and division, which are not commutative. But I'll write the code consistently for all four operators regardless, just to keep it clear and correct-by-construction.
Stage 4 — Code Walkthrough
Me
Candidate
Let me code it up. I'll use a set for O(1) operator lookup and handle each operator explicitly.
Python 3 — Evaluate RPN (walkthrough)
def evalRPN(tokens: list[str]) -> int:
    stack = []
    ops   = {'+', '-', '*', '/'}  # O(1) membership check

    for t in tokens:
        if t not in ops:
            stack.append(int(t))    # handles negatives like "-3" correctly
        else:
            b = stack.pop()         # right operand (pushed last → on top)
            a = stack.pop()         # left operand

            if   t == '+':  stack.append(a + b)
            elif t == '-':  stack.append(a - b)
            elif t == '*':  stack.append(a * b)
            else:           stack.append(int(a / b))  # truncate toward zero

    return stack[0]   # valid RPN always leaves exactly one element
Me

"1" → not op, push. stack=[2, 1]
"+" → op. b=pop()=1, a=pop()=2. push(2+1=3). stack=[3]
"3" → not op, push. stack=[3, 3]
"*" → op. b=pop()=3, a=pop()=3. push(3*3=9). stack=[9]

Me

No confusion at all. The check t not in ops uses the set {'+', '-', '*', '/'}, which contains only the single-character string "-". The token "-11" is a two-character string — it's not in the set, so it takes the number branch. int("-11") returns -11 correctly. The operator "-" is exactly one character, so there's no ambiguity.
Stage 5 — Complexity Analysis
Me
Candidate
Time: O(n) — a single pass through all n tokens. Each token results in O(1) work: either an int() conversion and a push, or two pops, one arithmetic operation, and a push. Set membership check is O(1).

Space: O(n) — in the worst case, all tokens are numbers and we push all of them before seeing any operators. The stack holds at most ⌈n/2⌉ elements (since valid RPN must have more operators as numbers accumulate).

There's no better time complexity — we have to examine every token at least once. The stack-based solution is optimal.

Stage 6 — Follow-up Questions
IV
Interviewer
Good solution. Three follow-ups: (1) How would you add support for exponentiation **? (2) If the input could be invalid, how would you detect that? (3) How does this compare to converting infix to postfix first?
Me
Candidate
(1) Adding **: Add '**' to the ops set and handle it in the elif chain: stack.append(a ** b). Note that exponentiation is right-associative — a ** b with a as the left operand is correct since we already pop in the right order. One line of code.

(2) Detecting invalid input: Two failure modes. First, if we try to pop from an empty stack when processing an operator — too few operands. Second, if the stack has more than one element at the end — too many operands, not enough operators. I'd wrap the pops in a try/except for IndexError and check len(stack) == 1 at the end.

(3) Infix vs. postfix: If given infix notation, you'd first convert it to postfix using the Shunting Yard algorithm — O(n) time — then evaluate the postfix with exactly this stack algorithm. RPN removes the need to handle operator precedence during evaluation since the conversion step already encoded it. For this problem, since the input is already in RPN, we skip that conversion entirely.
IV
Interviewer
Solid answers throughout. One last curiosity — why does a valid RPN expression always leave exactly one value on the stack?
Me
Candidate
It follows from the structure of a valid expression. Think of it inductively: a single number is a valid expression that leaves 1 element. Each binary operator consumes 2 elements and produces 1, so the stack size decreases by 1 per operator. A valid expression with k operators has exactly k+1 operand tokens. Starting at 0, after pushing k+1 numbers we're at k+1, and after k operators we're at k+1 − k = 1. So the final stack always has exactly one element — the result.

✅ Full Python Solution

Python 3 — Evaluate Reverse Polish Notation O(n) time · O(n) space 
def evalRPN(tokens: list[str]) -> int:
    stack = []
    ops   = {'+', '-', '*', '/'}

    for t in tokens:
        if t not in ops:
            stack.append(int(t))
        else:
            b, a = stack.pop(), stack.pop()  # b = right operand, a = left
            if   t == '+':  stack.append(a + b)
            elif t == '-':  stack.append(a - b)
            elif t == '*':  stack.append(a * b)
            else:           stack.append(int(a / b))  # truncate toward zero

    return stack[0]
Key Interview Tips 面试要点
  • Pop b before a — b is on top (right operand), a is below (left operand); order matters for - and /
  • Use int(a / b) not a // b for division — floor vs truncation diverge on negative results
  • int(t) handles negative number tokens like "-3" correctly; they won't match the single-char operator set
  • A valid RPN expression always ends with exactly one element on the stack — proof: n+1 numbers, n operators, net = 1
  • There is no simpler approach than O(n) — the stack solution is already optimal
