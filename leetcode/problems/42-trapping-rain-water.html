Trapping Rain Water
Hard Monotonic Stack
Problem Statement

Given n non-negative integers representing an elevation map where the width of each bar is 1, compute how much water it can trap after raining.

EXAMPLE
Input: height = [0,1,0,2,1,0,1,3,2,1,2,1]
Output: 6

The elevation map forms a terrain; the six shaded units of water are trapped in the valleys.
Constraints: 0 <= height[i] <= 105, 1 <= n <= 2 × 104.

💬 Mock Interview

Trapping Rain Water is one of two canonical hard monotonic stack problems (the other is #84 Largest Rectangle). It also admits an elegant two-pointer solution. Interviewers often want to see both approaches and a comparison. （经典难题，掌握单调栈和双指针两种解法）

Stage 1 — Problem Introduction
IV
Interviewer
Imagine you have a bar chart representing terrain heights, and it rains. How much water gets trapped between the bars? Given an integer array height, return the total units of trapped water. Take a moment to think about it.
Stage 2 — Clarifying Questions
Me
Candidate
Before I dive in, a few quick clarifications:
  • Heights are non-negative integers — can they be zero? A height of 0 is just a gap in the terrain?
  • If the array has fewer than 3 elements, water can't be trapped — is the answer 0 in that case?
  • Water can only be trapped between bars, not outside the two ends — so the leftmost and rightmost bars act as boundaries with no water on the outer side?
IV
Interviewer
All correct. Heights are non-negative and can be zero. Arrays with fewer than 3 elements trap no water. And yes — water can only be trapped between bars, never outside the edges.
Stage 3 — Approach Discussion
Me
Candidate
Let me think through a progression of approaches. The brute force observation is: for each bar at position i, water above it is min(max_left, max_right) - height[i], where max_left and max_right are the tallest bars to the left and right respectively. Scanning both directions for every bar gives O(n²) time.
IV
Interviewer
Good intuition on the formula. How can you improve beyond O(n²)?
We're recomputing max_left and max_right for every bar. If I precompute two arrays — left_max[i] and right_max[i] — I can answer each bar in O(1) after a linear pass. That's O(n) time and O(n) space. But there's also the two-pointer trick and the monotonic stack approach — each worth explaining.
Me
Candidate
The first improvement is to precompute prefix and suffix maximum arrays. One pass left-to-right builds left_max, one pass right-to-left builds right_max, then a final pass accumulates sum(min(left_max[i], right_max[i]) - height[i]). That's O(n) time and O(n) space — much better.

Two-pointer approach (O(n) time, O(1) space): Use pointers lo and hi starting at each end. Maintain running left_max and right_max. The key insight: if height[lo] < height[hi], we know the left side is the bottleneck — the water above lo is exactly left_max - height[lo] regardless of what's to the right, because the right side is at least as tall. So we process lo and advance it inward. Mirror logic for the right side.

Monotonic stack approach (O(n) time, O(n) space): Instead of thinking column-by-column, think layer-by-layer — compute water horizontally. Maintain a monotonically decreasing stack of indices. When we see height[i] > height[stack.top()], we've found the right wall of a valley. Pop the bottom, use the new stack top as the left wall, and accumulate (min(left_height, right_height) − bottom_height) × width.
IV
Interviewer
Great overview of all three. In the monotonic stack approach, why do you store indices rather than heights? And what does it mean geometrically when you pop an element?
Me
Candidate
We store indices because we need the width of the water layer — width = right_index − left_index − 1. Heights alone don't give us positions.

Geometrically, popping an element means we've found the bottom of a horizontal water layer. The element below it in the stack is the left wall, and the current bar i is the right wall. Water in that layer = (min(height[left], height[right]) − height[bottom]) × width. We keep popping — filling layers upward — until the stack becomes empty or the right wall is no longer taller than the new stack top. It's exactly like filling a container from the bottom up.
IV
Interviewer
After you pop the bottom, what happens if the stack is now empty? Why is that a special case?
Me
Candidate
If the stack is empty after popping, there is no left wall — the valley has no containing boundary on the left side, so no water can be held there. We break out of the while loop and push the current index. This is why the check if not stack: break comes immediately after the pop, before we try to access stack[-1] as the left wall.
Stage 4 — Pseudocode Walkthrough
Pseudocode — Monotonic Stack (Horizontal Layers)
function trap(height):
    stack = []          # decreasing stack of indices
    water = 0

    for i, h in enumerate(height):
        while stack and height[stack[-1]] < h:
            bottom = stack.pop()         # valley floor
            if not stack:
                break                    # no left wall — skip
            left           = stack[-1]  # left wall index
            width          = i - left - 1
            bounded_height = min(height[left], h) - height[bottom]
            water         += bounded_height * width
        stack.append(i)

    return water

IV
Interviewer
Good trace. The while loop can pop multiple times in one iteration — why doesn't that violate the O(n) complexity claim?
Me
Candidate
Amortised analysis: every index is pushed exactly once and popped at most once. The outer loop runs n times producing at most n pushes; the while loop across the entire run pops at most n times total. So total operations are bounded by 2n — still O(n).

Stage 6 — Follow-up Questions
IV
Interviewer
Can you walk me through the two-pointer approach? Why is it valid to process the shorter side without knowing the full picture on the other side?
Me
Candidate
The key insight is a monotonicity argument. Suppose height[lo] < height[hi]. Then whatever the right side looks like, the water above position lo is determined solely by left_max: it's left_max - height[lo] (or 0 if negative). Why? Because we know height[hi] ≥ height[lo], so the right boundary is at least as tall as the left boundary. The water level at lo is limited by left_max regardless of what's on the right. We can therefore safely accumulate water for lo and advance it inward. The symmetric argument applies when height[hi] ≤ height[lo].
IV
Interviewer
How does this problem compare to #84 Largest Rectangle in Histogram? They both use a monotonic stack — what's the fundamental geometric difference?
Me
Candidate
Both use a monotonic stack over bar heights, but the geometry is inverted:
  • #84 Largest Rectangle: We want to extend outward from a bar — looking for the nearest shorter bars on each side, which bound the rectangle. We pop when we find a shorter bar.
  • #42 Trapping Rain Water: We want to fill inward into valleys — we pop when we find a taller bar that acts as the right wall of a trapped region.
#84 pops on smaller elements (stack stays increasing by value), while #42 pops on larger elements (stack stays decreasing by value — or equivalently, we pop when height increases). Both share the amortised O(n) logic of each index being pushed and popped at most once.
IV
Interviewer
Last one: what if the elevation map were 2D — a grid of heights — and you needed to compute trapped water in 3D? How would you approach it?
Me
Candidate
That's LC #407 "Trapping Rain Water II". The 1D approaches don't extend directly because water can flow in four directions. The solution uses a min-heap (priority queue): seed it with all border cells, then use a BFS-like expansion. Always process the cell with the smallest height on the frontier. When we expand to a neighbour, any water it can hold is max(0, current_boundary_height - neighbour_height). We push the neighbour back with height max(neighbour_height, current_boundary_height) to propagate the water level correctly. Time complexity O(mn log(mn)) — the heap dominates.

✅ Full Python Solution

Python 3 — Monotonic Stack O(n) time · O(n) space 
class Solution:
    def trap(self, height: list[int]) -> int:
        stack = []
        water = 0
        for i, h in enumerate(height):
            while stack and height[stack[-1]] < h:
                bottom = stack.pop()
                if not stack:
                    break
                left           = stack[-1]
                width          = i - left - 1
                bounded_height = min(height[left], h) - height[bottom]
                water         += bounded_height * width
            stack.append(i)
        return water
Python 3 — Two Pointers (O(1) Space) O(n) time · O(1) space 
class Solution:
    def trap(self, height: list[int]) -> int:
        lo, hi         = 0, len(height) - 1
        left_max, right_max = 0, 0
        water          = 0
        while lo < hi:
            if height[lo] < height[hi]:
                if height[lo] >= left_max:
                    left_max = height[lo]
                else:
                    water += left_max - height[lo]
                lo += 1
            else:
                if height[hi] >= right_max:
                    right_max = height[hi]
                else:
                    water += right_max - height[hi]
                hi -= 1
        return water
Key Interview Tips 面试要点
  • The stack stores indices, not heights — you need positions to compute width
  • After popping bottom, always check if not stack: break before accessing stack[-1] as the left wall
  • Know all three O(n) approaches: prefix/suffix arrays, monotonic stack, two-pointer — interviewers may ask you to compare
  • Two-pointer is optimal on space (O(1)) but the correctness argument requires the monotonicity insight about the shorter side
  • Contrast with #84: rain water pops on taller bars (decreasing stack), histogram pops on shorter bars (increasing stack)
  • 3D extension → LC #407 uses a min-heap instead of a stack
