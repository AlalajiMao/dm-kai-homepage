Merge Two Sorted Lists
Easy Merge + Dummy Head Linked List
Problem Statement

You are given the heads of two sorted linked lists list1 and list2.

Merge the two lists into one sorted list. The list should be made by splicing together the nodes of the first two lists.

Return the head of the merged linked list.

EXAMPLE
Input: l1 = 1 → 2 → 4, l2 = 1 → 3 → 4
Output: 1 → 1 → 2 → 3 → 4 → 4

We interleave the nodes from both lists by always picking the smaller of the two current heads.

💬 Mock Interview

Merging sorted lists is a core primitive — it appears inside merge sort and is the foundation of the k-way merge heap used in #23. Mastering the dummy-head pattern here pays dividends across many problems.

Stage 1 — Problem Introduction
IV
Interviewer
Here's today's problem. You have two linked lists, both individually sorted in non-decreasing order. Your job is to merge them into a single sorted linked list using the existing nodes — no new nodes should be created. If the input is 1 → 2 → 4 and 1 → 3 → 4, the result should be 1 → 1 → 2 → 3 → 4 → 4. What's your initial read of the problem?
Me
Candidate
This is essentially the merge step from merge sort, but applied to linked lists instead of arrays. Since both lists are already sorted, at each step I can compare the two current heads and greedily pick the smaller one to append to the result. The tricky part is managing the pointer to the growing result list cleanly.
Stage 2 — Clarifying Questions
Me
Candidate
A few things I want to confirm:
  • Can either or both lists be empty? If one is empty, should I just return the other?
  • Are there duplicate values within or across the two lists? (Looks like yes from the example.)
  • The lists are sorted in non-decreasing order — equal elements are possible?
  • Should the merge be stable — preserving relative order among equal elements?
IV
Interviewer
Yes — either or both can be empty, just return the other. Duplicates are possible within and across lists. Sorted means non-decreasing. You don't need to worry about stability — just produce a valid sorted merged list.
Stage 3 — Approach Discussion
Me
Candidate
Let me think through the options:

Brute force — collect all values: Dump both lists into a Python list, sort the combined list, then rebuild linked nodes. That's O(n + m) time for traversal, O((n+m) log(n+m)) for the sort, and O(n+m) space for the auxiliary array. We can do better — we don't need to sort because both halves are already sorted.

Optimal — two-pointer merge with a dummy head: Create a dummy sentinel node to anchor the result list. Use a cur pointer starting at dummy. While both l1 and l2 are non-null, compare their values and append the smaller node to cur.next, then advance that list's pointer and advance cur. When one list is exhausted, attach the remaining tail of the other. Return dummy.next as the merged head.
The dummy head is the key insight here. Without it, I'd need a separate branch to initialize the head of the result list. With a dummy, the logic is uniform: always do cur.next = (smaller node), advance. The dummy's cost is one extra node — negligible — but it eliminates all the messy "is this the first node?" bookkeeping.
Me
Candidate
The dummy-head approach is O(n + m) time and O(1) extra space — we're just rewiring existing nodes. Shall I walk through the pseudocode and a trace?
IV
Interviewer
Please do.
Stage 4 — Pseudocode & Trace
Pseudocode
function mergeTwoLists(l1, l2):
    dummy = ListNode(0)     # sentinel — never returned directly
    cur   = dummy

    while l1 and l2:
        if l1.val <= l2.val:
            cur.next = l1         # append l1's node
            l1       = l1.next
        else:
            cur.next = l2         # append l2's node
            l2       = l2.next
        cur = cur.next           # advance the result pointer

    cur.next = l1 if l1 else l2   # attach the remaining tail
    return dummy.next             # skip the sentinel
Me
Candidate
Let me trace through l1 = 1→2→4, l2 = 1→3→4:

Initial: dummy→[0], cur=dummy, l1=1, l2=1

Step 1: l1.val(1) <= l2.val(1) → cur.next = l1(1), l1→2, cur→node(1)
  Result so far: dummy→1

Step 2: l1.val(2) > l2.val(1) → cur.next = l2(1), l2→3, cur→node(1)
  Result so far: dummy→1→1

Step 3: l1.val(2) <= l2.val(3) → cur.next = l1(2), l1→4, cur→node(2)
  Result so far: dummy→1→1→2

Step 4: l1.val(4) > l2.val(3) → cur.next = l2(3), l2→4, cur→node(3)
  Result so far: dummy→1→1→2→3

Step 5: l1.val(4) <= l2.val(4) → cur.next = l1(4), l1→None, cur→node(4)
  Result so far: dummy→1→1→2→3→4

Loop ends (l1 is None). cur.next = l2(4) → attach remaining tail.
Final: dummy→1→1→2→3→4→4
Return dummy.next = 1→1→2→3→4→4 ✅
IV
Interviewer
Good. What if l1 is empty?
Me
Candidate
If l1 is None, the while loop body never executes. We hit cur.next = l1 if l1 else l2, which sets cur.next = l2. So we return dummy.next = l2 — exactly the right answer. Same logic applies if both are empty: we return dummy.next = None.

Stage 6 — Follow-up Questions
IV
Interviewer
How would you extend this to merge k sorted linked lists?
Me
Candidate
For k lists (LeetCode #23), a naive approach — repeatedly call this merge function on pairs — gives O(kN) time where N is the total number of nodes. The efficient approach uses a min-heap of size k: push the head of each non-null list into the heap. Then repeatedly pop the minimum node, append it to the result, and push that node's next onto the heap if it exists. This runs in O(N log k) time since each heap operation is O(log k) and we do N of them.
IV
Interviewer
Can you solve this recursively?
Me
Candidate
Yes — base cases: if either list is None, return the other. Otherwise, pick the smaller head, set its next to merge(rest_of_that_list, other_list), and return it. It's elegant but uses O(n + m) stack space, so the iterative version is preferred in production.
IV
Interviewer
What if one of the lists were circular?
Me
Candidate
A circular list has no None terminator, so the while loop would spin forever. I'd need to detect the cycle first — using Floyd's algorithm — find the tail, temporarily break the cycle, merge, then decide whether to re-attach. In practice, the problem contract guarantees acyclic lists, but it's worth mentioning as a defensive check.

✅ Full Python Solution

Python 3 — Merge Two Sorted Lists O(n+m) time · O(1) space 
class Solution:
    def mergeTwoLists(
        self,
        l1: Optional[ListNode],
        l2: Optional[ListNode]
    ) -> Optional[ListNode]:
        dummy = ListNode(0)    # sentinel — anchors the result list
        cur   = dummy

        while l1 and l2:
            if l1.val <= l2.val:
                cur.next = l1
                l1       = l1.next
            else:
                cur.next = l2
                l2       = l2.next
            cur = cur.next

        cur.next = l1 if l1 else l2  # attach the remaining tail
        return dummy.next               # skip the sentinel
Key Interview Tips 💡
  • The dummy head pattern eliminates all "is this the first node?" branching — always use it for list construction.
  • Use <= not < when comparing values so equal elements from both lists are handled correctly without bugs.
  • After the loop, one list might still have nodes — cur.next = l1 if l1 else l2 attaches the entire remaining tail in one line.
  • Always return dummy.next, never dummy — the sentinel is a scaffold, not part of the answer.
  • This is the exact merge step inside merge sort — mentioning that connection shows algorithmic breadth.
  • The recursive version is elegant but costs O(n+m) stack space — prefer iterative when space matters.
