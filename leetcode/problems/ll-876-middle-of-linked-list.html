Middle of the Linked List
Easy Fast & Slow Pointers Linked List
Problem Statement

Given the head of a singly linked list, return the middle node of the linked list.

If there are two middle nodes, return the second middle node.

EXAMPLES
Input: 1 → 2 → 3 → 4 → 5  →  Output: node 3 (the unique middle)
Input: 1 → 2 → 3 → 4 → 5 → 6  →  Output: node 4 (the second of two middles)

For a list of length 5, index 2 (0-based) is the single middle. For a list of length 6, indices 2 and 3 are both "middles" — return index 3.

Stage 3 — Approach Discussion
Me
Candidate
There are two main approaches here.

Brute force — two passes: First traverse the entire list to count the length n, then traverse again to reach the n // 2th node (0-indexed). That's O(n) time but requires two full traversals and O(1) space.

Optimal — fast/slow pointers: Use two pointers starting at head. On each step, slow moves one node and fast moves two. When fast can no longer advance (it's None or its next is None), slow is exactly at the middle — in one pass, O(1) space.
The key insight: fast travels at 2× speed. When fast has covered the full list, slow has covered exactly half. For even-length lists, the condition while fast and fast.next stops with fast on the last node (not past it), which naturally lands slow on the second middle. That's the behavior we want.
Me
Candidate
I'll go with the fast/slow pointer approach — single pass, O(1) space. The condition while fast and fast.next is the precise condition that gives us the second middle for even-length lists, which matches the requirement.
IV
Interviewer
Good. Go ahead and walk me through it.
Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode:
Pseudocode
function middleNode(head):
    slow = fast = head          # both start at head

    while fast and fast.next:   # fast can still advance two steps
        slow = slow.next          # slow moves +1
        fast = fast.next.next     # fast moves +2

    return slow                   # slow is at the middle
Me
Candidate
Let me trace through both examples manually.

Odd-length list: 1 → 2 → 3 → 4 → 5
Start: slow=1, fast=1
Step 1: slow=2, fast=3   (fast moved to node 3)
Step 2: slow=3, fast=5   (fast moved to node 5)
Check: fast=5, fast.next=None → loop ends
Return slow=node 3 ✅

Even-length list: 1 → 2 → 3 → 4 → 5 → 6
Start: slow=1, fast=1
Step 1: slow=2, fast=3
Step 2: slow=3, fast=5
Check: fast=5, fast.next=6 (not None) → continue
Step 3: slow=4, fast=None (fast moved past end)
Check: fast=None → loop ends
Return slow=node 4 ✅ (second middle, as required)
IV
Interviewer
Great trace. Just to make sure you understand the loop condition — why do we check both fast and fast.next?
Me
Candidate
fast being truthy handles odd-length lists — fast lands on None after the last node and we stop. fast.next handles the case where fast is on the last node — we can't move two steps forward from there, so we stop. Both checks prevent a NoneType attribute error when we do fast.next.next inside the loop.
Stage 5 — Complexity Analysis
Me
Candidate
Time: O(n) — we traverse at most n/2 steps with the slow pointer, and fast covers n steps total, but we still touch all nodes once. Linear.

Space: O(1) — only two pointer variables, no extra data structures. This is the optimal solution for both dimensions.

Stage 6 — Follow-up Questions
IV
Interviewer
Follow-up: what if you wanted the first middle for even-length lists instead of the second?
Me
Candidate
Change the loop condition to while fast.next and fast.next.next. This stops fast one step earlier — when fast is at the second-to-last node rather than the last node — so slow ends up one position to the left, at the first middle. For the 6-node example, slow would return node 3 instead of node 4.
IV
Interviewer
Interesting. Where else does finding the middle of a linked list show up as a sub-problem?
Me
Candidate
Two big ones come to mind immediately:

Palindrome check (LeetCode #234): Find the middle, reverse the second half in-place, then compare left and right halves. The whole algorithm depends on correctly locating the middle first.

Merge sort on a linked list: You find the middle to split the list into two halves, recursively sort each half, then merge. The fast/slow pointer is the standard way to find the split point.
IV
Interviewer
Perfect. That's exactly the context this pattern lives in. Great job.

✅ Full Python Solution

Python 3 O(n) time · O(1) space 
class Solution:
    def middleNode(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        return slow
Key Interview Tips 💡
  • The condition while fast and fast.next is the exact formulation for "second middle" — memorise this.
  • To get the first middle for even-length lists, use while fast.next and fast.next.next instead.
  • Always trace both an odd-length and an even-length example to verify the off-by-one behaviour.
  • Mention this sub-problem by name when solving palindrome or merge-sort problems — it signals pattern recognition.
  • The two-pointer approach is strictly better than the two-pass approach: same O(n) time, same O(1) space, but one traversal.
