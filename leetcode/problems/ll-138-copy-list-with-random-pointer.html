Copy List with Random Pointer
Medium HashMap Linked List
Problem Statement

A linked list of length n is given such that each node contains an additional random pointer, which could point to any node in the list, or null.

Construct a deep copy of the list. The deep copy should consist of exactly n brand-new nodes, where each new node has its value set to the value of its corresponding original node. Both the next and random pointer of the new nodes should point to new nodes in the copied list, not to nodes in the original list.

EXAMPLE
Input: [[7,null],[13,0],[11,4],[10,2],[1,0]]
(each pair is [val, random_index])
Output: Deep copy with identical structure

Node 13's random points to index 0 (val 7). Node 11's random points to index 4 (val 1). All pointers in the copy must reference new nodes, never originals.

💬 Mock Interview

The difficulty here is that random pointers can point forward or backward in the list — so when you try to set new_node.random, the target copy may not exist yet. A hash map that maps each original node to its copy solves this elegantly with a two-pass approach.

Stage 1 — Problem Introduction
IV
Interviewer
Each node in this linked list has a next pointer and also a random pointer that can jump to any node in the list or be null. I want a complete deep copy — brand-new nodes with no references back into the original list. How would you approach this?
Me
Candidate
The hard part is the random pointer. If I try to copy nodes and wire random pointers in a single pass, the target copy might not exist yet — the random pointer could point forward to a node I haven't created. I need to separate "create all nodes" from "connect all pointers." A hash map from original to copy lets me do that cleanly in two passes.
Stage 2 — Clarifying Questions
Me
Candidate
Before I start coding:
  • Can the list be empty? I'll return null in that case.
  • Can random point to the same node as next, or to the node itself?
  • Is there any constraint on extra space, or is O(n) space for the hash map acceptable?
  • Do node values have to be unique? (Shouldn't matter — I'm using node identity, not values, as map keys.)
IV
Interviewer
Yes, the list can be empty — return null. Random can point anywhere, including self-loops. O(n) space is fine for now. Values are not necessarily unique.
Stage 3 — Approach Discussion
Me
Candidate
Two approaches:

Hash map, two passes — O(n) time, O(n) space:
Pass 1: traverse the original list; create a new node for every original node and store the mapping old_node → new_node in a dictionary.
Pass 2: traverse again; for each original node, set new.next = map[old.next] and new.random = map[old.random] (with null checks).

Interleave trick — O(n) time, O(1) space:
Insert each copy directly after its original: A → A' → B → B' → .... Wire randoms using node.random.next. Then detach the two lists. More complex to implement but removes the hash map.
The two-pass hash map is the correct answer to reach for in an interview — it is clear, correct, and easy to justify. The O(1)-space interleave trick is an impressive follow-up. Never try to wire next and random in a single pass — the forward-pointing randoms will reference original nodes that don't yet have copies.
Me
Candidate
I'll implement the hash map approach. The code is short and easy to verify correct — I can mention the interleave optimization afterward.
IV
Interviewer
Sounds good. Show me the pseudocode and trace through [[7,null],[13,0],[11,4]].
Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode:
Pseudocode
function copyRandomList(head):
    if not head: return None

    # Pass 1: create all new nodes
    old_to_new = {}
    cur = head
    while cur:
        old_to_new[cur] = Node(cur.val)
        cur = cur.next

    # Pass 2: wire next and random pointers
    cur = head
    while cur:
        if cur.next:
            old_to_new[cur].next   = old_to_new[cur.next]
        if cur.random:
            old_to_new[cur].random = old_to_new[cur.random]
        cur = cur.next

    return old_to_new[head]
Me
Candidate
Tracing [[7,null],[13,0],[11,4]] — nodes A(7), B(13), C(11).
B's random → A (index 0). C's random → null (index 4 doesn't exist here, so I'll treat it as null for this trace).

Pass 1 — create copies:
  cur=A(7): old_to_new[A] = A'(7)
  cur=B(13): old_to_new[B] = B'(13)
  cur=C(11): old_to_new[C] = C'(11)
All three copies exist. No pointers wired yet.

Pass 2 — wire pointers:
  cur=A: A'.next = B'  (old_to_new[A.next=B]) · A'.random = None (A.random is null)
  cur=B: B'.next = C'  (old_to_new[B.next=C]) · B'.random = A' (old_to_new[B.random=A])
  cur=C: C'.next = None (C.next is null) · C'.random = None

Result: A'(7) → B'(13) → C'(11) → None, with B'.random = A'. Deep copy complete ✅
No original nodes are referenced by any copy node.
IV
Interviewer
Clear trace. Why can't you wire the random pointer in the same pass as creating the node?
Me
Candidate
Because random can point forward. If node A's random points to node C, and I try to set A'.random = old_to_new[C] during Pass 1 at step A, C's copy hasn't been created yet — old_to_new[C] would raise a KeyError. By separating creation and wiring into two passes, all copies exist by the time we wire any pointer in Pass 2.
Stage 5 — Complexity Analysis
Me
Candidate
Time: O(n) — two passes, each visiting every node once.

Space: O(n) — the hash map stores one entry per original node. The output list itself is O(n) but that's required output, not auxiliary space.

Stage 6 — Follow-up Questions
IV
Interviewer
Can you solve this with O(1) extra space?
Me
Candidate
Yes — the interleave trick. Three phases:
Phase 1: Insert each copy right after its original: A → A' → B → B' → ...
Phase 2: Wire random pointers: node.next.random = node.random.next (A'.random = A.random.next, which is the copy of A's random target).
Phase 3: Detach the two lists by restoring all next pointers.
This is O(1) auxiliary space but is significantly harder to implement without bugs, so I'd mention it as an optimization after getting the hash-map version working.
IV
Interviewer
Where does this pattern appear in real systems?
Me
Candidate
Anywhere you need to deep copy an object graph with internal references — serialization, undo/redo buffers, copy-on-write semantics, cloning a game state. The same hash-map pattern (identity map) is used in graph deep-copy and in memoized serialization of cyclic object graphs. The key insight is always: build all copies first, then wire pointers.

✅ Full Python Solution

Python 3 — Copy List with Random Pointer O(n) time · O(n) space 
class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        if not head:
            return None

        # Pass 1: create all new nodes, map old → new
        old_to_new = {}
        cur = head
        while cur:
            old_to_new[cur] = Node(cur.val)
            cur = cur.next

        # Pass 2: wire next and random pointers
        cur = head
        while cur:
            if cur.next:
                old_to_new[cur].next   = old_to_new[cur.next]
            if cur.random:
                old_to_new[cur].random = old_to_new[cur.random]
            cur = cur.next

        return old_to_new[head]
Key Interview Tips 💡
  • State upfront why two passes are needed: forward-pointing randoms mean the target copy may not exist during Pass 1.
  • Use old_to_new[cur.random] — not Node(cur.random.val). You must look up the same copy, not create a duplicate.
  • Always null-check: if cur.next and if cur.random before indexing the map.
  • The hash map keys are node objects (identity), not values — this handles duplicate values correctly.
  • Mention the O(1)-space interleave trick as a follow-up to show awareness of the optimization, but don't attempt it without getting the hash-map version working first.
  • This pattern generalizes to deep-copying any graph — the same hash map serves as the "already cloned" registry to handle cycles.
