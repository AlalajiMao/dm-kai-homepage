Linked List Cycle II
Medium Fast & Slow Pointers Linked List
Problem Statement

Given the head of a linked list, return the node where the cycle begins. If there is no cycle, return null.

There is a cycle in a linked list if there is some node in the list that can be reached again by continuously following the next pointer. Do not modify the linked list.

EXAMPLES
Input: 3 → 2 → 0 → -4, tail connects back to index 1
Output: node with val 2

Input: 1 → 2, tail connects back to index 0
Output: node with val 1

Floyd's two-phase algorithm detects the cycle entry in O(n) time and O(1) space — no hash set needed.

💬 Mock Interview

This problem extends #141 from "does a cycle exist?" to "where does it start?" The clever part is Floyd's Phase 2 math: after the fast and slow pointers meet inside the cycle, resetting one pointer to head and advancing both at speed 1 brings them together exactly at the cycle entry node.

Stage 3 — Approach Discussion
Me
Candidate
Two approaches:

Brute force — hash set: Traverse the list, inserting each node into a set. The first node we try to insert that's already in the set is the cycle entry. O(n) time, O(n) space. Simple and correct, but uses extra memory.

Optimal — Floyd's two-phase algorithm: O(n) time, O(1) space.
Phase 1: Use a slow pointer (1 step) and fast pointer (2 steps). If they meet, a cycle exists.
Phase 2: Reset one pointer to head. Keep the other at the meeting point. Advance both at speed 1 — they meet at the cycle entry.

The math: let F = distance from head to entry, C = distance from entry to meeting point, L = cycle length. At the meeting: slow traveled F+C, fast traveled F+2C+k·L. Since fast = 2·slow: F = k·L − C. So the meeting point is exactly F steps from the cycle entry, matching the head distance F. That's why resetting one pointer works.
The key insight is purely algebraic: F = (k-1)·L + (L-C). Distance from meeting point back to cycle entry equals L-C. Distance from meeting point to entry going forward is also L-C. And F steps from head reaches entry. So both pointers walking at speed 1 converge at the entry. No need to actually know F, C, or L — the math works out automatically.
Me
Candidate
I'll implement Floyd's two-phase approach for O(1) space. Should I walk through the pseudocode?
IV
Interviewer
Yes, show me the pseudocode and trace through the example 3 → 2 → 0 → -4 → (back to 2).
Stage 4 — Pseudocode & Trace
Me
Candidate
Here's the pseudocode:
Pseudocode
function detectCycle(head):
    slow = fast = head

    # Phase 1: find meeting point inside cycle
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:          # meeting point found
            # Phase 2: find cycle entry
            ptr = head
            while ptr is not slow:
                ptr  = ptr.next
                slow = slow.next
            return ptr             # cycle entry node

    return None                    # no cycle
Me
Candidate
Let me trace 3(0) → 2(1) → 0(2) → -4(3) → back to 2(1).
Indices in parens; cycle entry is node 2 (index 1).

Phase 1 — find meeting point:
Start: slow=3, fast=3
Step 1: slow=2, fast=0 (fast took two steps: 3→2→0)
Step 2: slow=0, fast=2 (fast: 0→-4→2, wraps via cycle)
Step 3: slow=-4, fast=-4 (slow: 0→-4; fast: 2→0→-4)
slow is fast — meeting point is node -4.

Phase 2 — find entry:
ptr=3 (head), slow=-4
Step 1: ptr=2, slow=2 (slow: -4→2 via cycle)
ptr is slow — both at node 2. Return node 2 ✅
IV
Interviewer
Good trace. What happens when there is no cycle at all?
Me
Candidate
If there is no cycle, the fast pointer will eventually reach null (either fast becomes null or fast.next becomes null). The while condition fails, we skip Phase 2 entirely, and return None — exactly the correct answer.
Stage 5 — Complexity Analysis
Me
Candidate
Time: O(n) — Phase 1 takes at most O(n) steps to find the meeting point. Phase 2 takes at most O(n) more steps to find the entry. Both phases are linear in the list length.

Space: O(1) — only three pointer variables: slow, fast, and ptr. No auxiliary data structures.

Stage 6 — Follow-up Questions
IV
Interviewer
What is the key difference between this problem and #141 Linked List Cycle?
Me
Candidate
LC #141 only asks does a cycle exist? — you can return true the moment slow and fast meet inside Phase 1. LC #142 asks where does it start? — you need Phase 2 to locate the actual entry node. The Phase 1 code is identical; #142 just adds the second loop.
IV
Interviewer
Can you find the length of the cycle once you have the entry?
Me
Candidate
Yes — once I have the entry node, I start a pointer there and keep advancing it, counting steps, until it returns to the entry node. That count is exactly the cycle length L. This adds one more O(L) pass but L ≤ n, so the overall complexity stays O(n) time, O(1) space.
IV
Interviewer
How would you solve this if you were allowed O(n) extra space?
Me
Candidate
Use a hash set of visited nodes. Traverse the list; insert each node. The first node we encounter that is already in the set is the cycle entry — return it. If traversal ends (null), return null. This is O(n) time and O(n) space. It is simpler to reason about than Floyd's, but fails the space constraint.

✅ Full Python Solution

Python 3 — Linked List Cycle II O(n) time · O(1) space 
class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:
                # Phase 2: find the cycle entry
                ptr = head
                while ptr is not slow:
                    ptr  = ptr.next
                    slow = slow.next
                return ptr

        return None
Key Interview Tips 💡
  • Name the two phases explicitly — "Phase 1: find meeting point" and "Phase 2: find entry" — it shows structured thinking.
  • The Phase 2 loop condition is ptr is not slow, not ptr.val != slow.val — you are comparing node identity, not values.
  • You don't need to memorize the proof. Just say: "F steps from head equals F steps from the meeting point, so resetting one pointer to head and walking both at speed 1 converges at the entry."
  • If the interviewer asks for the O(n) space solution first, give the hash-set approach, then offer to optimize to O(1).
  • Edge cases: empty list and single node with no self-loop both exit Phase 1 immediately and return null correctly.
  • Mention that #141 is a strict subset — the Phase 1 code is identical; this problem just adds Phase 2.
