Decode String
Medium Stack Simulation Nested Structure
Problem Statement

Given an encoded string, return its decoded version. The encoding rule is k[encoded_string], where encoded_string inside the brackets is repeated exactly k times. You may assume the input is always valid.

Encodings may be nested.

EXAMPLES
s = "3[a]2[bc]" → "aaabcbc"
s = "3[a2[c]]" → "accaccacc"
s = "2[abc]3[cd]ef" → "abcabccdcdcdef"

Stage 3 — Approach Discussion
Me
Candidate
The nesting is the key signal here. Whenever I see a nested structure where I need to "pause" outer work, do inner work, then "resume," that's a stack pattern.

My mental model: think of the stack as saving context. When I open a bracket '[', I'm entering a deeper level — I push the current string and current count onto the stack and start fresh. When I close a bracket ']', I'm returning to the outer level — I pop the saved context, repeat the current string by the saved count, and prepend the saved string.

Concretely, I track two variables at any moment: cur_str (string being built at the current nesting level) and cur_num (the number being accumulated before a '[').
The stack stores pairs of (saved_string, repeat_count) — one pair per nesting level. The current variables always represent the innermost level we're actively processing.
IV
Interviewer
That's the right framing. Can you trace through "3[a2[c]]" step by step?
Me
Candidate
Sure. I start with cur_str="", cur_num=0, stack=[].

'3' → digit: cur_num=3.
'[' → push ("", 3). Reset: cur_str="", cur_num=0.
'a' → letter: cur_str="a".
'2' → digit: cur_num=2.
'[' → push ("a", 2). Reset: cur_str="", cur_num=0.
'c' → letter: cur_str="c".
']' → pop ("a", 2). cur_str = "a" + "c" * 2 = "acc".
']' → pop ("", 3). cur_str = "" + "acc" * 3 = "accaccacc".

Return "accaccacc" ✅
Stage 4 — Pseudocode & Code
Me
Candidate
The pseudocode maps very cleanly onto the four character types:
Pseudocode
function decodeString(s):
    stack = []
    cur_str, cur_num = "", 0

    for ch in s:
        if ch is a digit:
            cur_num = cur_num * 10 + int(ch)     # handle multi-digit k

        elif ch == '[':
            stack.push((cur_str, cur_num))       # save outer context
            cur_str, cur_num = "", 0             # start fresh inner level

        elif ch == ']':
            prev_str, num = stack.pop()           # restore outer context
            cur_str = prev_str + cur_str * num    # expand and prepend outer

        else:
            cur_str += ch                          # regular letter, accumulate

    return cur_str

Similarly "2[abc]3[cd]ef": after processing the two bracket groups, cur_str is "abcabccdcdcd", then 'e' and 'f' append to give "abcabccdcdcdef" ✅

Stage 5 — Complexity Analysis
Me
Candidate
Time: O(n × max_k) where n is the length of the output string. Each character in the decoded output is produced once, but string repetition costs O(|result|). In terms of input length alone, O(n) traversal — but the output can be exponentially larger than the input for deeply nested high-k encodings.

Space: O(n × max_k) for the output strings, plus O(d) stack depth where d is the nesting depth. Since d ≤ 30 per constraints, the stack overhead is effectively O(1) relative to the output size.

Stage 6 — Follow-up Questions
IV
Interviewer
Three follow-ups: (1) Can you solve this recursively instead of iteratively? (2) How does memory usage scale if I keep increasing the nesting depth and k values? (3) What if the encoding also supported character ranges like 3[a-c]?
Me
Candidate
(1) Recursive approach: Yes — instead of an explicit stack we use the call stack. Pass an index into the string; when you hit '[', recurse and let the recursive call consume up to the matching ']', returning both the decoded segment and the updated index. The iterative and recursive solutions are equivalent — the explicit stack mirrors the call stack exactly.

(2) Memory scaling: If nesting depth is d and each level repeats k times, the output length grows as k^d. For k=10 and d=30 that's 10^30 characters — completely impractical to materialize. In a real system you'd use lazy/streaming evaluation or represent the result as a tree of (count, segment) nodes rather than fully expanding it.

(3) Character ranges: We'd need to expand a-c into "abc" during the decoding step — a preprocessing pass on the content inside brackets. The stack-based structure remains the same; we just add a helper that expands range syntax when building cur_str.
IV
Interviewer
Solid answers. The observation about the tree representation for lazy evaluation is exactly how real compression schemes handle this. Thanks — that's all.

✅ Full Python Solution

Python 3 — Decode String O(output) time · O(output) space 
class Solution:
    def decodeString(self, s: str) -> str:
        stack: list[tuple[str, int]] = []
        cur_str, cur_num = "", 0

        for ch in s:
            if ch.isdigit():
                cur_num = cur_num * 10 + int(ch)    # build multi-digit k
            elif ch == '[':
                stack.append((cur_str, cur_num))    # save outer context
                cur_str, cur_num = "", 0            # enter inner level
            elif ch == ']':
                prev_str, num = stack.pop()          # restore outer context
                cur_str = prev_str + cur_str * num   # expand and rejoin
            else:
                cur_str += ch                         # accumulate letters

        return cur_str
Key Interview Tips 面试要点
  • Push both cur_str and cur_num on '[' — you need both to restore outer context
  • Multi-digit numbers need the num * 10 + digit accumulation pattern
  • On ']', the order is: prev_str + cur_str * num — outer string comes first
  • Letters outside any brackets are handled naturally by the else branch — no special casing needed
  • This exact pattern generalizes to any problem with nested structure (e.g. nested JSON, HTML tags)
