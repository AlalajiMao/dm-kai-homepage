Remove All Adjacent Duplicates in String II
Medium Stack + Aux Info
Problem Statement

Given a string s and an integer k, repeatedly remove groups of k adjacent identical characters until no more groups exist. Return the final string.

Removals may cascade — after one group is deleted, adjacent characters may form a new group of k.

EXAMPLE
Input: s = "deeedbbcccbdaa", k = 3
Output: "aa"

"deeedbbcccbdaa" → remove "eee" → "dbbcccbdaa" → remove "ccc" → "dbbdbdaa" → remove "bb" → "ddbdaa"... actually the cascade can resolve in different orders; the final result is always the same: "aa".

SIMPLER EXAMPLE (for tracing)
Input: s = "pbbcggp", k = 2
Output: "pcp"

💬 Mock Interview

The naive approach re-scans the string after every removal — O(n²/k). The stack insight is that we can process the string in a single left-to-right pass by tracking (character, count) pairs, handling cascading removals automatically. （栈存字符+计数对，自动处理级联删除）

Stage 3 — Approach Discussion
Me
Candidate
The naive approach re-scans and rebuilds the string on every pass. Each pass is O(n) and we might need O(n/k) passes in the worst case, giving O(n²/k) — potentially O(n²) total. For long strings that's going to be too slow.
IV
Interviewer
Agreed. What's the efficient approach?
The key observation: as I process characters left to right, I'm really building up consecutive runs. If I track (char, count) pairs on a stack, whenever count reaches k I can pop that pair — the removal is instant. After the pop, the previous top of the stack is now adjacent to whatever comes next, so cascading is handled automatically. I never need to re-scan.
Me
Candidate
The elegant approach is a stack that stores (character, count) pairs instead of individual characters. Here's the logic for each character ch:
  • If the stack is non-empty and stack[-1][0] == ch, increment its count.
  • Otherwise, push (ch, 1).
  • After updating, if the count at the top reaches k, pop that pair — those k characters are removed.
Cascading is handled for free: once a group is popped, the previous top is now the active character, and the next character will compare against it naturally.
IV
Interviewer
Why does this handle cascading correctly without any extra logic?
Me
Candidate
Because the stack's top always represents the most recent active character group. After we pop a completed group, the new top is precisely the character immediately before that group in the original string. When we push the next character, it compares against this new top — exactly what we'd want if we had physically deleted the group and spliced the string. No re-scan needed; the stack naturally "remembers" the context.
Stage 4 — Pseudocode and Trace
Pseudocode — Stack of (char, count) Pairs
function removeDuplicates(s, k):
    stack = []          # list of (char, count) pairs

    for ch in s:
        if stack and stack[-1][0] == ch:
            stack[-1] = (ch, stack[-1][1] + 1)   # extend current run
        else:
            stack.append((ch, 1))               # new character, count=1

        if stack[-1][1] == k:
            stack.pop()                          # group complete → remove

    return ''.join(ch * cnt for ch, cnt in stack)
Me
Candidate
Let me trace "pbbcggp", k=2:
ch='p': stack empty → push (p,1). stack=[(p,1)]
ch='b': top is 'p' ≠ 'b' → push (b,1). stack=[(p,1),(b,1)]
ch='b': top is 'b' → count→2. count==k → pop (b,2). stack=[(p,1)]
ch='c': top is 'p' ≠ 'c' → push (c,1). stack=[(p,1),(c,1)]
ch='g': top is 'c' ≠ 'g' → push (g,1). stack=[(p,1),(c,1),(g,1)]
ch='g': top is 'g' → count→2. count==k → pop (g,2). stack=[(p,1),(c,1)]
ch='p': top is 'c' ≠ 'p' → push (p,1). stack=[(p,1),(c,1),(p,1)]
Result: 'p'*1 + 'c'*1 + 'p'*1 = "pcp" ✅

Notice how when 'bb' was popped, the next character 'c' correctly compared against 'p' — the cascade would work the same way for longer chains.

Interviewer

Me

ch='a': push (a,1). stack=[(a,1)]
ch='a': count→2. stack=[(a,2)]
ch='a': count→3. count==k=3 → pop. stack=[]
ch='a': stack empty → push (a,1). stack=[(a,1)]

Stage 6 — Follow-up Questions
IV
Interviewer
How would you modify this if, instead of returning the final string, you needed to return the list of all characters removed and in what order?
Me
Candidate
Whenever we pop a (ch, k) group, append ch * k to a removal log. The log records the order of removals — each pop corresponds to one batch removal event. Time and space remain O(n) since the total characters removed is still bounded by n.
IV
Interviewer
What if k = 1? Does your algorithm handle that correctly?
Me
Candidate
Yes — every character we push immediately reaches count=1=k, so it's popped right away. Every character is removed, the stack stays empty throughout, and we return an empty string. That's the correct answer: k=1 means remove every single character.
IV
Interviewer
Could you store character indices instead of (char, count) pairs? What would that look like?
Me
Candidate
You could, but it's more complex. You'd push each character index onto the stack and track the count by comparing the current character with the character two positions below in the stack. The (char, count) pair approach is cleaner because the count is explicit and you don't need to look several levels deep to find the start of the current run. I'd stick with (char, count) in an interview for clarity.

✅ Full Python Solution

Python 3 — Remove All Adjacent Duplicates II O(n) time · O(n) space 
class Solution:
    def removeDuplicates(self, s: str, k: int) -> str:
        stack = []  # list of [char, count] pairs (list so we can mutate count)

        for ch in s:
            if stack and stack[-1][0] == ch:
                stack[-1][1] += 1          # extend the current run
            else:
                stack.append([ch, 1])     # start a new run

            if stack[-1][1] == k:
                stack.pop()               # run complete — remove it

        return ''.join(ch * cnt for ch, cnt in stack)
Implementation Note

Use lists [ch, count] instead of tuples (ch, count) so you can mutate the count in place with stack[-1][1] += 1. With tuples you'd have to replace the entire top element: stack[-1] = (ch, stack[-1][1] + 1). Either works — pick whichever you find more readable and state it clearly.

Key Interview Tips 面试要点
  • Store (char, count) pairs, not just chars — the count is what makes O(n) possible
  • Cascading removals are handled automatically — explain this clearly, it's the insight examiners want to hear
  • k=1 edge case removes everything — verify your algorithm handles it without special-casing
  • Use mutable lists [ch, cnt] if you want in-place count increment; tuples require full replacement
