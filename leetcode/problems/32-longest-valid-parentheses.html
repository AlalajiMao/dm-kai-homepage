Longest Valid Parentheses
Hard Bracket Matching
Problem Statement

Given a string containing just the characters '(' and ')', return the length of the longest valid (well-formed) parentheses substring.

EXAMPLES
Input: s = ")()())"
Output: 4   — the substring "()()" has length 4

Input: s = "(()"
Output: 2   — the substring "()" has length 2

Input: s = ""
Output: 0

💬 Mock Interview

Longest Valid Parentheses is a deceptively tricky hard problem. The stack approach uses a clever sentinel value to eliminate edge-case handling. There's also a beautiful O(1) space two-pass solution — knowing both signals strong preparation. （哨兵值是关键，理解为什么初始化为 [-1]）

Stage 1 — Problem Introduction
IV
Interviewer
You're given a string of only '(' and ')'. Find the length of the longest well-formed parentheses substring. A substring must be contiguous, and it must be completely valid — every open paren has a matching close. What's your initial read on this?

  • If no valid substring exists — say the input is all ')' — the answer is 0?

Stage 3 — Approach Discussion
Me
Candidate
The naive approach would check all O(n²) substrings and validate each in O(n), giving O(n³) total. We can validate a substring in O(n) with a counter, but the overall complexity is still bad. Let me think about something smarter.
IV
Interviewer
O(n³) is indeed too slow. What patterns do you see that could help?
Valid parentheses involve matching — a stack is the natural fit. The classic #20 Valid Parentheses uses a stack to track unmatched opens. Here the question is about the length of matched regions. If I track the positions of unmatched characters, the gaps between them are valid substrings. A stack of indices could work. I need to be careful about what happens at the very start and at unmatched closing brackets — a sentinel base index handles both cleanly.
Me
Candidate
I'll think of this as tracking positions of unmatched characters. A stack lets me do that in one pass. Here's the key insight:

Seed the stack with a sentinel -1. As I scan:
  • On '(': push its index.
  • On ')': pop the top. If the stack becomes empty, this ')' is unmatched — push its index as the new base. Otherwise, the valid length ending here is i - stack.top().
The sentinel -1 acts as a virtual "last unmatched" position before the string starts, so the very first valid substring is correctly computed as i - (-1) = i + 1.
IV
Interviewer
Why exactly does i - stack.top() give the length? Walk me through the geometry.
Me
Candidate
After we pop to match a ')' at index i, whatever remains on the stack top is the index of the last unmatched character — either an unmatched ')' or the sentinel. The valid substring runs from stack.top() + 1 up to i, so its length is i - stack.top(). We don't add 1 because the top itself is not part of the valid region — it's the boundary just before it begins.
IV
Interviewer
Good. What if there are two separate valid substrings that aren't adjacent — like "()()()"? Does the algorithm correctly return 6?
Me
Candidate
Yes — let me trace it:
stack=[-1]
i=0 '(': push 0. stack=[-1,0]
i=1 ')': pop 0. stack=[-1]. len=1-(-1)=2. max=2
i=2 '(': push 2. stack=[-1,2]
i=3 ')': pop 2. stack=[-1]. len=3-(-1)=4. max=4
i=4 '(': push 4. stack=[-1,4]
i=5 ')': pop 4. stack=[-1]. len=5-(-1)=6. max=6
The sentinel -1 persists as the base throughout, so each closing paren that empties the stack back to the sentinel correctly measures the cumulative valid run from the very beginning — automatically merging adjacent valid substrings into one length.
Stage 4 — Pseudocode Walkthrough
Pseudocode — Stack with Sentinel
function longestValidParentheses(s):
    stack   = [-1]        # sentinel: last unmatched position before string
    max_len = 0

    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)         # push index of open paren
        else:                          # ch == ')'
            stack.pop()               # try to match with top
            if not stack:
                stack.append(i)     # unmatched ')' becomes new base
            else:
                max_len = max(max_len, i - stack[-1])

    return max_len
Me
Candidate
Full trace of ")()())":
stack=[-1]
i=0 ')': pop -1. stack empty → push 0. stack=[0]
i=1 '(': push 1. stack=[0,1]
i=2 ')': pop 1. stack=[0]. len=2-0=2. max=2
i=3 '(': push 3. stack=[0,3]
i=4 ')': pop 3. stack=[0]. len=4-0=4. max=4
i=5 ')': pop 0. stack empty → push 5. stack=[5]
Return 4 ✅ — the substring at indices 1–4 is "()()".
IV
Interviewer
Clean. Can you mention the DP approach as well?
Me
Candidate
Sure. Define dp[i] = length of the longest valid substring ending at index i. Only ')' positions can end a valid substring, so dp[i] = 0 whenever s[i] == '('. For s[i] == ')', there are two sub-cases:
  • s[i-1] == '(': they directly match. dp[i] = dp[i-2] + 2 (extend the valid run ending two positions back).
  • s[i-1] == ')': the character before the valid run ending at i-1 might match s[i]. Let j = i - dp[i-1] - 1. If s[j] == '(', then dp[i] = dp[i-1] + 2 + dp[j-1].
This is also O(n) time and O(n) space, same as the stack approach. I personally find the stack approach more intuitive to derive under pressure.

Stage 6 — Follow-up Questions
IV
Interviewer
You mentioned a two-pass O(1) space approach. How does it work?
Me
Candidate
Use two counters: left and right. In the first pass (left to right): increment left on '(', increment right on ')'. When left == right, record 2 * right as a candidate max. When right > left, reset both to zero — there are more closes than opens, so we've broken any valid run.

The first pass catches all valid substrings that aren't cut off by excess closes. But it misses cases like "(()" where we run out of closes — left stays ahead of right forever. The second pass (right to left) with swapped roles catches those: increment right on ')', left on '(', record max when equal, reset when left > right. Together the two passes cover all valid substrings.
IV
Interviewer
How does this problem relate to #20 Valid Parentheses? What's the key difference in what's being asked?
Me
Candidate
#20 asks: is the entire string valid? — a binary yes/no. A simple counter or stack works. #32 asks: what is the longest valid contiguous portion? — a length question over all possible substrings. The added difficulty is tracking where valid regions start and end, and merging adjacent valid regions. The sentinel trick in #32's stack approach is precisely what handles that boundary tracking, which #20 never needs.
IV
Interviewer
What if you needed to return the actual substring rather than just its length?
Me
Candidate
The stack approach makes this easy. Instead of just tracking max_len, also track best_start and best_end. Whenever we compute a new candidate length i - stack[-1] that beats the current max, record best_start = stack[-1] + 1 and best_end = i. At the end, return s[best_start : best_end + 1]. The two-pointer counter approach would need extra bookkeeping — the stack approach wins here.

✅ Full Python Solution

Python 3 — Stack with Sentinel O(n) time · O(n) space 
class Solution:
    def longestValidParentheses(self, s: str) -> int:
        stack   = [-1]    # sentinel base index
        max_len = 0
        for i, ch in enumerate(s):
            if ch == '(':
                stack.append(i)
            else:
                stack.pop()
                if not stack:
                    stack.append(i)    # unmatched ')' becomes new base
                else:
                    max_len = max(max_len, i - stack[-1])
        return max_len
Python 3 — Two-Pass Counter (O(1) Space) O(n) time · O(1) space 
class Solution:
    def longestValidParentheses(self, s: str) -> int:
        max_len = 0
        for direction in (1, -1):         # left-to-right, then right-to-left
            lo, hi   = (0, len(s)) if direction == 1 else (len(s) - 1, -1)
            open_ch  = '(' if direction == 1 else ')'
            left, right = 0, 0
            for i in range(lo, hi, direction):
                if s[i] == open_ch:
                    left  += 1
                else:
                    right += 1
                if left == right:
                    max_len = max(max_len, 2 * right)
                elif right > left:
                    left = right = 0
        return max_len
Key Interview Tips 面试要点
  • Seed the stack with [-1] — this sentinel acts as the base boundary before the string starts and eliminates all edge-case handling
  • Length formula: i - stack[-1] (not i - stack[-1] + 1) — the stack top is the last unmatched character, one position before the valid run
  • When ')' empties the stack, push the current index as the new base — it is now the boundary before the next valid run
  • The two-pass counter achieves O(1) space but needs two passes; mention it to show breadth, but implement the stack for clarity first
  • If asked to return the actual substring: track best_start = stack[-1] + 1 whenever you update max_len
  • Contrast with #20: #20 checks the whole string (binary), #32 finds the best valid portion (length) — different goals, different tools
