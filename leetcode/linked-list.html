🔗 Linked List

A sequence of nodes where each node holds a value and a pointer to the next — built for O(1) insert/delete once you have the location.
链表 — 指针操作是核心，画图再写代码

Core Idea 核心思路
Unlike arrays, linked lists have no index-based random access (traversal is O(n)), but support O(1) insert/delete once you hold a reference to the target node. Nearly every linked list problem reduces to careful pointer re-wiring — always draw the before/after state before writing a single line of code.
动笔画图再写代码，是链表题的黄金法则

Node Definition & Core Operations

Python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val  = val
        self.next = next

# Build: 1 → 2 → 3 → None
head = ListNode(1, ListNode(2, ListNode(3)))

# Traverse — O(n)
cur = head
while cur:
    print(cur.val)
    cur = cur.next

# Insert after node p — O(1)
new_node.next = p.next
p.next = new_node

# Delete node after p — O(1)
p.next = p.next.next  # GC handles memory

Traverse O(n) · Insert/Delete at known position O(1) · Search O(n)

Pattern 1 — Fast & Slow Pointers

Trigger Keywords 触发关键词
"middle of linked list", "detect cycle", "find cycle entry", "palindrome linked list", "nth from end" — any problem that needs two positions in the list simultaneously without extra space.
Core Insight 核心思路

Move slow one step and fast two steps per iteration.

  • Find middle: when fast hits the end, slow is at the midpoint.
  • Detect cycle: if a cycle exists, fast will lap slow and they'll meet inside the loop.
  • Find cycle entry (LC #142): after meeting, reset one pointer to head and advance both at speed 1 — they meet at the entry node.
快指针跑两步，慢指针跑一步，相遇即为中点

Core Template

Pseudocode — Fast & Slow (Find Middle)
function findMiddle(head):
    slow, fast = head, head

    while fast and fast.next:
        slow = slow.next          # 1 step
        fast = fast.next.next    # 2 steps

    return slow                  # slow is at the middle

# ── Cycle detection variant ──────────────────────────────
function hasCycle(head):
    slow, fast = head, head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast: return True   # they met — cycle!
    return False

Pattern 2 — In-place Reversal

Trigger Keywords 触发关键词
"reverse a linked list", "reverse between positions m and n", "reverse in k-group", "palindrome linked list" — any problem requiring the direction of next pointers to be flipped.
Core Insight 核心思路
Use three pointers: prev, cur, nxt. At each step: save nxt = cur.next, flip cur.next = prev, then advance both. The invariant is that everything to the left of cur is already reversed.
三指针法：保存下一个，翻转当前，整体右移

Core Template

Pseudocode — Iterative Reversal
function reverseList(head):
    prev, cur = None, head

    while cur:
        nxt      = cur.next     # ① save next before overwriting
        cur.next = prev         # ② flip pointer
        prev     = cur          # ③ advance prev
        cur      = nxt          # ④ advance cur

    return prev                  # prev is now the new head

# ── Partial reversal (between left and right) ─────────────
function reverseBetween(head, left, right):
    dummy = ListNode(0, head)   # dummy head eliminates edge cases
    pre   = dummy
    for _ in range(left - 1): pre = pre.next  # stop at node before left

    cur = pre.next
    for _ in range(right - left):
        nxt      = cur.next
        cur.next = nxt.next
        nxt.next = pre.next      # insert nxt right after pre
        pre.next = nxt

    return dummy.next

Pattern 3 — Dummy Head Node

Trigger Keywords 触发关键词
"remove nth node", "delete node", "remove duplicates", "swap pairs", "merge two sorted lists" — any problem where the head itself might be deleted or replaced, or where you need a consistent predecessor for every node.
Core Insight 核心思路
Create a dummy = ListNode(0, head) before the real head. Now every node in the original list (including the first) has a predecessor, so deletion and insertion are always "delete/insert after some node" — no special-case for head. Return dummy.next at the end (the real head may have changed).
哨兵消灭边界情况，dummy.next 就是真实头
Pseudocode — Dummy Head (Remove Nth From End)
function removeNthFromEnd(head, n):
    dummy       = ListNode(0, head)   # fake node before head
    fast, slow  = dummy, dummy

    # advance fast by n+1 steps to create a gap of n
    for _ in range(n + 1): fast = fast.next

    # move both until fast hits the end
    while fast:
        fast = fast.next
        slow = slow.next

    # slow is now at the node BEFORE the one to delete
    slow.next = slow.next.next

    return dummy.next            # head might have changed!
Trace — Remove 2nd from end of 1→2→3→4→5 (n=2)
dummy → 1 → 2 → 3 → 4 → 5 → None
Advance fast 3 steps (n+1=3): fast points to 3
Move both until fast=None: slow=3, fast=None
slow.next (4) is the target → slow.next = slow.next.next (5)
Result: 1 → 2 → 3 → 5 → None ✓
Complexity 复杂度
O(n) time — one pass with the two-pointer gap technique. O(1) space — dummy node + two pointers only.

Pattern 4 — Merge & Divide

Trigger Keywords 触发关键词
"merge two sorted lists", "merge k sorted lists", "sort a linked list" — whenever you need to combine or sort linked list structures efficiently.
Core Insight 核心思路

Merging two sorted linked lists is O(m+n) with a pointer race — no extra array needed. Merge sort on a linked list is optimal (O(n log n)) because splitting at the middle is O(n) via fast/slow, and no extra space is needed for merging.

For k lists, use a min-heap of size k (O(n log k)) or pair-wise merge with divide-and-conquer.

链表的归并排序比数组更自然，不需要额外空间合并

Core Template — Merge Two Sorted Lists

Pseudocode — Merge Two Sorted (LC #21)
function mergeTwoLists(l1, l2):
    dummy = ListNode(0)        # dummy head → no edge-case for first node
    cur   = dummy

    while l1 and l2:
        if l1.val <= l2.val:
            cur.next = l1;  l1 = l1.next
        else:
            cur.next = l2;  l2 = l2.next
        cur = cur.next

    cur.next = l1 if l1 else l2   # attach remaining tail
    return dummy.next

Pattern 5 — HashMap + Pointer

Trigger Keywords 触发关键词
"copy list with random pointer", "detect cycle entry point", "intersection of two linked lists", "LRU cache" — problems where you need to track identity of nodes (not just values) or achieve O(1) lookup on a list structure.
Core Insight 核心思路

Hash maps let you move from O(n) search to O(1) lookup by mapping node identity → metadata.

  • Deep copy: map old_node → new_node; then rewire next and random in a second pass.
  • Cycle entry: store visited nodes; first repeat is the entry. (O(n) space — Floyd's is the O(1) alternative.)
  • LRU Cache: doubly-linked list (O(1) evict) + hash map (O(1) lookup) = O(1) get/put.
哈希表换空间换时间，链表+哈希 = LRU的核心
Pseudocode — Copy List with Random Pointer (LC #138)
function copyRandomList(head):
    if not head: return None
    old_to_new = {}    # maps original node → its copy

    # Pass 1: create all new nodes
    cur = head
    while cur:
        old_to_new[cur] = Node(cur.val)
        cur = cur.next

    # Pass 2: wire next and random pointers
    cur = head
    while cur:
        if cur.next:
            old_to_new[cur].next   = old_to_new[cur.next]
        if cur.random:
            old_to_new[cur].random = old_to_new[cur.random]
        cur = cur.next

    return old_to_new[head]
Complexity 复杂度
Deep Copy (hash map): O(n) time, O(n) space for the map.
LRU Cache get/put: O(1) amortised — doubly-linked list + hash map combo.
Cycle entry (hash set): O(n) time, O(n) space — use Floyd's for O(1) space.
