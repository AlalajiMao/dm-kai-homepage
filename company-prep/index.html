Databricks Interview Style
Coding rounds often have multiple edge cases pushed during the interview — the expectation is a clean, correct first pass. Design problems frequently extend into concurrency + durability (locks, WAL, snapshots). Always ask thread-safety and scale requirements upfront. Problems marked DB Original have no public LC link.
Section I — Coding / Algorithm 13 problems

Intervals
1272 Remove Interval Medium Intervals Iterate each interval; emit non-overlapping fragments. Three cases: fully before toRemove → keep whole; fully after → keep whole; overlapping → emit left stub [start, toRemove[0]) and/or right stub (toRemove[1], end] if non-empty. Watch open vs. closed boundary — both endpoints are inclusive in this problem.
DB DB Original Delete Index from Interval Medium Intervals Given non-overlapping intervals and an index into their flattened coverage list, delete that element and return the updated interval array.
Example: [(4,7),(10,11),(13,15)], index 2 → covered[2] = 6 → output [(4,5),(7,7),(10,11),(13,15)]
Clean O(n) approach: walk intervals accumulating count; when count + size > index, found the target interval. offset = index − count; split into [start, start+offset−1] and [start+offset+1, end] (skip empty fragments).
⚠ Edge cases pushed live: offset == 0 (no left frag), offset == size−1 (no right frag), single-point interval disappears. Write clean, first-pass correct code.
Sliding Window
438 Find All Anagrams in a String
aka "Anagrammed indexOf"
 Medium Sliding Window Fixed window of len(p); maintain a char-count diff counter (need = number of unsatisfied chars). Add right char (decrement need if count hits 0), evict left char (increment need if count drops below 0). Record index when need == 0.
Dynamic Programming
198 House Robber Medium DP (1-D) dp[i] = max(dp[i−1], dp[i−2] + nums[i]). Space-optimize to two rolling variables.
213 Follow-up 1 House Robber II (circular) Medium DP (1-D) Run House Robber twice: on nums[0..n−2] and nums[1..n−1], return the max. Handles "can't rob first and last."
— Follow-up 2 House Robber with gap-k Medium DP (1-D) Must leave at least k houses between each robbery. Transition: dp[i] = max(dp[i−1], dp[i−k−1] + nums[i]). Base cases: dp[j] = nums[j] for j < k+1.
Tree / Math
DB DB Original Find Path in Fibonacci Tree Hard Tree / Recursion Tree definition: T(1) and T(2) are single nodes. T(k) has T(k−1) as left subtree and T(k−2) as right. Nodes are labeled by pre-order index. Given two pre-order indices a, b, return the path between them without building the tree.
O(k) approach: compute size(k) = 1 + size(k−1) + size(k−2) (Fibonacci-like). For any node index, recurse: if index == 1 → root; if index ≤ left-size+1 → go left; else → go right. Reconstruct root-to-a and root-to-b paths, find LCA, concatenate.
Graph / BFS / DFS
695 Max Area of Island Medium BFS / DFS Flood-fill BFS/DFS; mark visited by zeroing the cell. Return max connected area of 1s. If interviewer says "don't mutate input" → use a visited set instead.
787 Cheapest Flights Within K Stops Medium Graph (Bellman-Ford) Bellman-Ford for exactly k+1 relaxation rounds; copy cost array each round to prevent intra-round chaining. BFS with state (node, stops_left, cost) also works. Dijkstra requires state (node, stops_remaining) to avoid revisiting.
DB DB Original HQ → SF Commute (BFS travel modes) Medium BFS / Graph Graph where each edge has a travel-mode (walk / bike / transit) with a cost. Optimize: shortest time first, then lowest cost as tiebreak.
⚠ Interviewer emphasis: confirm edge weights are fixed before reaching for Dijkstra. Fixed weights → plain BFS. Variable weights → priority queue.
State = (node, time, cost); keep visited map to avoid re-expanding with worse state.
Design (coding)
1146 Snapshot Array
+ SnapshotSet variant
 Medium Design / Binary Search LC 1146: per-index list of (snap_id, val); get(idx, snap_id) uses bisect_right on snap_ids.
Databricks SnapshotSet variant: supports put(x), remove(x), snapshot() → Iterator. The iterator must be isolated: later put/remove calls on the live set must not affect any already-created iterator. Implement with copy-on-write: snapshot() freezes the current set and returns an iterator over the frozen copy.
981 Time Based Key-Value Store
aka "KV Store"
 Medium Design / Binary Search dict[key] → sorted list of (timestamp, value). get(key, t): bisect_right(timestamps, t) − 1; return "" if index < 0. Expect follow-up on persistence and concurrent writes.
348 Design Tic-Tac-Toe Medium Design rows[n], cols[n], diag, anti_diag counters — player 1 adds +1, player 2 −1. Win when any counter reaches ±n. O(1) per move, O(n) space.
Databricks variant: board size n and win-length k are both configurable (not necessarily n×n win-all-in-row). Extend: maintain rows[n] etc. but check against k, not n.
362 Design Hit Counter
aka "HashMap with QPS"
 Medium Design Coding part: circular buffer of size 300; hits[t % 300] = (timestamp, count). For sparse/high-precision: deque of timestamps, pop stale from left.
System-design follow-up (durable KV + high QPS):
(1) Fine-grained locks on the in-memory map (per-key or striped locks).
(2) WAL: every write appended to log before in-memory apply; entries = (key, value, seq).
(3) Snapshot coordination: after a successful snapshot, open a new WAL file; recovery = load latest snapshot + replay only the newest WAL file.
Bit Manipulation
DB DB Original IP CIDR Firewall Rule Matching Hard Bit Manipulation Ordered rules of (CIDR, ALLOW|DENY); return whether target IP is allowed. CIDR match: mask = ~0 << (32 − prefix_len); match iff (ip & mask) == (network & mask). Iterate rules in order — first match wins.
Follow-up: given a new CIDR block, determine if it is entirely allowed (all IPs it covers are allowed). Requires range arithmetic: check that no DENY rule's range overlaps the new block before any covering ALLOW rule.
Section II — Design / OOD 4 problems
Design Round Tips
These are open-ended OOD questions — start with data structures and interfaces, then layer in concurrency. Always propose a simple single-threaded version first, then discuss locking strategy.
✓ Problem Core Challenge Description & Key Points
Concurrency
Revenue System 		Hard
Heap / Graph 		API: insert(revenue) → customer_id (no referrer), insert(revenue, referrer) → customer_id, get_top_k_revenue(k, min_revenue) → Set[int].
Revenue definition: total = own revenue + sum of direct referees' revenues (one hop only).
Key design questions: (1) How to maintain top-k efficiently under frequent inserts? Options: min-heap of size k (O(log k) per insert), sorted structure, or recompute on query. (2) Thread-safety: concurrent insert calls must not corrupt the referrer map or revenue sums — use per-customer locks or a read-write lock on the referrer graph.
Lazy Eval
Lazy Array 		Medium
Functional 		API: map(fn) → LazyArray, indexOf(target) → int.
map() appends fn to an unevaluated operation chain and returns a new LazyArray (original unchanged, chains are independent).
indexOf() is the only terminal operation — it applies the full chain to each element in order until a match is found.
Example: arr.map(x→x*2).indexOf(40) → 1; arr.map(x→x*2).map(x→x*3).indexOf(240) → 3
⚠ Core test: use a mock/counter wrapper to prove map() makes zero function calls. If the interviewer sees eager evaluation you fail the laziness requirement.
Concurrency
Circuit Breaker 		Hard
State Machine 		Three states: CLOSED (normal), OPEN (fail-fast after N consecutive failures), HALF_OPEN (one probe request after recoveryTimeout elapses).
HALF_OPEN probe succeeds → back to CLOSED, reset failure counter.
HALF_OPEN probe fails → back to OPEN, reset timer.
Concurrency critical path: in HALF_OPEN, exactly one thread must get the probe slot; all others must still be rejected. Use AtomicReference + CAS for the state transition, or a ReentrantLock with a "probing" flag. Naive synchronized on the whole method creates a thundering-herd problem when OPEN expires.
Compression
Encoding & Decoding 		Medium
Bit Manipulation 		Mixed encoding for integer arrays (mirrors Parquet / Databricks Delta columnar encoding):
• If a run of identical values has length ≥ 8 → encode as RLE run: (value, count).
• Otherwise → pack up to 8 consecutive values into a BP (bit-pack) literal run.
decode(runs) → original array must perfectly invert both run types.
Follow-ups: compute compression ratio; handle trailing chunk < 8 values; extend to streaming/incremental encoding (can't look ahead). Mention that this is close to the RLE+BP hybrid used in Apache Parquet's RLE_DICTIONARY encoding.
